# RainFX v2 — 물방울 구현 방향 정리와 단계 계획 (사용자 제안 기반, 2026-10-27)

## 1. 사용자 제안(rev22 리뷰)

1. **외형 통일:** 물방울 외형의 기준은 `ref_OBJECTIVES/RainFX구현목표_물방울형태및흐름_입체감과윤곽및하이라이트_물방울이동과trail형태_크기분포.mp4` 하나.
   디포커스와 다양한 크기가 상황에 맞게 섞이면 다른 레퍼런스에도 근접한다.
2. **크기 혼합:** 상황별로 다양한 크기를 섞는다.
3. **디포커스는 마지막:** 바이저 효과 전체(방울·수막·haze·trail)에 일관되게 적용하며, 모든 효과가 완료된 뒤 구현한다.
4. **흐름:** 물리(상대 바람, 중력 등)로 이동 — 현행 유지.
5. **trail:** 이동하며 trail을 남기고 작아진다. 정도는 크기·속도에 따른 일관된 규칙. 이동하며 기존 방울과 합쳐져 함께 흐르고, 결과적으로 닦인다.

rev22 결과: FXC 9 OK. 격자는 사라졌으나 정렬된 느낌이 남고, 직진 시 바이저 중앙면에 물이 계속 고여 정렬이 잘 드러난다.

## 2. 기준 영상 측정 (`docs/tools/rainfx2_dropsize_ref.py`)

방법: 밝은 배경 위 방울의 어두운 초승달(Y − blur σ15 < −12)을 연결 성분으로 세고, 크기 = 경계 상자 긴 변(px). 5프레임(1·3·5·7·9 s).

| | 밀도 (100×100 px당) | p50 | p90/p50 | p97/p50 | p99/p50 | 로그 구간 히스토그램(1.5배 구간) |
|---|---|---|---|---|---|---|
| 기준 영상 (720 px 폭) | 12.0 | 7 px | 3.4 | 6.6 | **13** | 3→1336, 5→1073, 8→759, 12→532, 18→338, 27→186, 40→95, 60→43: **단조 감소** |
| v2 rev21 T4 PNG (3240 px) | 12.3 | 9 px | 2.8 | 4.5 | **6.2** | 3→793, 5→445, 8→482, **12→590**, 18→343 …: **12–18 px에 혹** |

해석:
- 기준 영상은 작은 방울이 가장 많고 클수록 일정 비율(구간당 ×0.7)로 줄어드는 멱법칙형 분포이며 꼬리가 길다(가장 큰 방울은 중앙값의 13배 이상).
- v2는 특정 크기에 혹이 있고(비슷한 크기가 많음) 꼬리가 짧다. **비슷한 크기 + 셀당 하나**가 "정렬된 느낌"의 주원인이다.
  크기가 섞이면 같은 셀 구조에서도 규칙성이 눈에 덜 띈다(기준 영상도 같은 크기끼리는 간격이 비교적 고르다 — 합체가 간격을 고르게 만든다).
- 외형(기준 영상): 한쪽(위)만 어둡고 굵은 초승달, 반대쪽은 배경에 녹음, 몸통은 밝은 배경을 그대로 보임, 큰 방울 안에 작은 반사점.
  흐르는 방울 뒤로 **작은 방울들이 줄지어 남는 trail**(가는 선이 아니라 점렬).

목표 지표(같은 스크립트로 v2 Debug 0 PNG 측정): 히스토그램 단조 감소, p90/p50 ≈ 3–3.5, p99/p50 ≥ 10.

## 3. 단계 계획

디포커스는 제안대로 마지막 단계로 미룬다. 그동안 **aperture 기본 0(꺼짐)** 으로 두어 외형·크기 판단에 섞이지 않게 한다(D-A/D-C 코드는 유지).

### 단계 1 (rev23) — 외형을 기준 영상에 맞춤
- rev22의 먼 림 렌즈(한쪽 초승달)를 기준 영상 프레임과 같은 조건(밝은 하늘 배경)에서 비교·보정: 초승달 두께·어둡기(farMix, farMip, edgeLoss).
- 큰 방울(R > 1 mm)의 작은 반사점(하늘 방향 글린트를 점 형태로) — 현 glint는 림 띠 형태.
- 오프라인 비교: 기준 프레임과 v2 렌즈 규칙 재현 이미지를 나란히(`docs/prototypes`), 사용자 판정.

### 단계 2 (rev23–24) — 크기 혼합(멱법칙형)
- 탄생: 파편 크기를 평균 하나가 아니라 넓은 분포로(파편 수 n개 중 하나를 크기 분포에서 표본; 지수 DSD × 파편화 비율의 분산 확대).
- 성장: 합체가 큰 방울을 만든다(현행). 큰 쪽 꼬리는 합체·trail 수거로 생긴다.
- 정체 구역(직진 시 중앙): 기류가 법선 방향이라 접선 공기력 ≈ 0 → 작은 방울이 영원히 고정·누적. 실제로는 헬멧 주변 난류가 접선 성분을 흔든다.
  **난류 접선 성분**(자유류의 10–15 %, 셀·시간별 무작위, 수십 ms 상관)을 공기력에 더해 정체 구역 방울도 가끔 움직이고 합쳐지게 한다(흔들림과 같은 원리로 확장).
- 검증: 위 지표(히스토그램 단조 감소, 꼬리 비율).

### 단계 3 (rev24–25) — 흐름·trail·합쳐짐·닦임의 일관 규칙
- **trail = 점렬:** 움직이는 방울은 이동 거리당 부피를 잃고(현행 trailLoss·travel·r²), 잃은 부피가 일정량 모이면 지나간 빈 셀에 **작은 방울 하나를 남긴다**
  (실제 pearling: 꼬리가 끊겨 작은 방울이 줄지어 남음). 남는 방울 크기·간격은 r과 속도로 정한다: 빠를수록(모세관수 Ca 클수록) 촘촘·작게.
  trail 필드(T)는 haze를 닦는 얇은 막 표시로만 남긴다.
- **휩쓸어 합치기:** 현재 합체(claim/merge)는 "프레임 시작 시 닿아 있는 방울"만 합친다. 이동한 방울은 **이동 선분**이 다른 방울과 r1 + r2 안에 들어오면 합친다
  (claim 패스의 거리 판정을 점 → 선분으로). 큰 방울이 흐르며 길 위 방울을 모아 커지고, 지나간 자리는 trail 점렬만 남아 닦인 모습이 된다.
- 가속: 합쳐져 커진 방울은 같은 힘에서 더 빨라진다(물리 현행) → 흐름이 연쇄적으로 길을 만든다(rev21 흔적 따라가기와 결합).

### 단계 4 (마지막) — 바이저 전체 디포커스
- 방울만이 아니라 수막·haze·trail·산란까지 같은 CoC로. D-B(별도 층)는 preview728에서 불가로 확인 → 후보:
  (a) 바이저 효과를 **바이저 UV 공간 캔버스**에 먼저 합성(굴절 상 제외, 덮임·색 계수만)한 뒤 그리기 단계에서 CoC 크기 mip로 읽기,
  (b) 현 D-A 탭을 효과 전체 평가로 확장(비용 큼).
  (a)가 결정적이고 싸다(UV 캔버스는 이미 field/state가 그 공간). 단계 3 완료 후 상세 설계.

## 4. 확인 요청

순서(외형 → 크기 혼합·정체 구역 → trail·휩쓸어 합치기 → 전체 디포커스)와 "디포커스 끄고 진행"에 동의하면 단계 1·2를 rev23으로 구현한다.

## 5. 사용자 결정과 진행 (2026-10-27)

- 단계 1(외형)부터 진행, 다른 기능을 차단한 관찰 환경 마련 → rev23 Look lab(CORE §33).
- **운동 방향 메모(사용자):** 현실 법칙대로 airflow를 바이저 법선까지 고려해 투영하면 게임에서는 공기력이 가장 세고 방울이 **위쪽·좌우로** 흐른다.
  실제 주행 영상에서는 바람을 맞기 시작하면 **아래로** 강하게 흐른다. 방울이 무거워서인지 실제 기류가 아래로 향하는지(헬멧·차체 주변 유동) 알 수 없고,
  차량 공기역학을 모델링할 수 없으므로 **단계 3에서 관찰 기반 보정**이 필요하다. 후보: 바이저 표면 기류 방향장(위치별 접선 기류 방향을 아래로 꺾는 보정 계수,
  예: 투영된 접선 기류에 화면 아래 방향 성분을 섞는 `airDownBias`), 레퍼런스 영상의 흐름 방향을 위치별로 측정해 맞춘다.
