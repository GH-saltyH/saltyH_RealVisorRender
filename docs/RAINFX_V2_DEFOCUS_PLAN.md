# RainFX v2 — 디포커스 분석과 제안 (rev18 착수 전, 2026-10-26)

사용자 관찰(rev17): 거리 기반 디포커스가 바람직하다. 레퍼런스에서도 카메라 바로 앞인 바이저 오른쪽은 흐리고, 먼 왼쪽은 선명하다.
rev17의 aperture는 물 모양(Debug 1의 빨강) 자체를 강하게 바꾸고, 빛을 굴절해야 할 방울이 굴절하지 못하는 면처럼 보인다.
일반적인 카메라 초점처럼 흐리고 번지는 정도여야 한다.

오프라인 비교: `docs/prototypes/rainfx2_defocus_compare.py` → `docs/rainfx2_defocus_options.jpg`
(왼쪽 열 = 화면 왼쪽(먼 쪽), 오른쪽 열 = 렌즈 바로 앞; 위에서부터 ①선명 ②정답(색 층 블러) ③D-C ④rev17식 광선 평균).

## 1. rev5–rev17 디포커스가 모양과 굴절을 망가뜨린 이유

rev5의 방식은 "픽셀마다 동공 footprint(지름 = aperture, 바이저 mm)가 덮는 물의 비율과 **평균 광선**"이었다.

1. **모양(Debug 1 꽃잎·프로펠러):** 덮임 f를 원–원 겹침 근사로 구했는데, 방울 반지름 rEff가 픽셀 방향각의 함수(윤곽 노이즈 3배음)라서
   footprint가 방울보다 크면(rb > rEff) 각도별로 겹침이 크게 달라진다 → 2–3엽 프로펠러. 디포커스가 "흐림"이 아니라 **새 모양**을 만든다.
2. **굴절 소실:** footprint 안 기울기를 평균하면 방울 양쪽의 반대 방향 기울기가 상쇄된다(중심을 향하는 벡터의 평균 ≈ 0).
   평균 광선 하나로 장면을 샘플하므로 방울이 **배경을 그대로 통과시키는 탁한 면**이 된다. 분산은 mip(최대 8)으로만 반영돼 뭉개진다.
3. **물리적으로 틀린 순서:** 실제 카메라 디포커스는 *방울이 이미 굴절한 결과 영상*을 착란원(CoC)으로 평균한다. 즉 **색의 평균**이지 기울기·광선의 평균이 아니다.
   비교 이미지 ④가 이 실패(찢긴 모양, 굴절 없는 면)를 재현하고, ②가 올바른 결과(오른쪽은 희미하고 부드러운 원판, 왼쪽은 선명)다.

## 2. 거리 기반 착란원(CoC)

얇은 렌즈, 초점 거리 zf, 입사동 지름 A, 바이저 점까지 거리 z:

- 바이저 면 위 블러 지름(물체 공간): `c_mm = A · |zf − z| / zf`
- 화면 블러 지름: `c_px = c_mm · f_px / z` (f_px = 0.5·H / tan(fovY/2))

z ≪ zf이면 c_mm ≈ A로 일정하지만 c_px ∝ 1/z라서 렌즈에 가까운 오른쪽(z ≈ 2–3 cm)이 왼쪽(10–12 cm)보다 수 배 흐리다.
레퍼런스처럼 왼쪽이 **선명**하려면 초점이 바이저 왼쪽 근처(zf ≈ 0.1–0.15 m)에 있어야 한다(소형 온보드 카메라의 근거리 초점으로 타당).
프로토타입 값 A 1.2 mm, zf 0.12 m: 왼쪽 CoC ≈ 0 px, 오른쪽 ≈ 45 px(1920 폭).

z는 셰이더에서 공짜다: CSP `mesh.fx`의 `pin.PosC`(카메라 기준 위치) → `z = length(pin.PosC)`. (주석이 "far clipping plane"이라 되어 있어 게임에서 Debug 뷰로 검증 필요. 실패 시 물체→월드 행렬과 카메라 위치로 계산.)
UI: `Aperture (mm)`, `Focus distance (m)`, 패널에 바이저 좌·중·우 CoC px 표시.

## 3. 원칙

**방울 모양과 렌즈는 항상 선명하게 계산하고(rev18 WF 렌즈), 디포커스는 그 결과 색에만 적용한다.** 실루엣·기울기·굴절 방향은 CoC로 바꾸지 않는다.

## 4. 구현 선택지

|안|방법|정확도|비용(근접 위치 바이저 픽셀)|위험|
|---|---|---|---|---|
|**D-C 해석 근사**|실루엣 경계를 CoC 폭으로 부드럽게(부호 거리 = (U − 0.35)/|∇U|), 덮임 × (R/(R + c/2))²(에너지 보존), 굴절 상 mip += ½·log2(1 + 0.35·c_px·렌즈 축소율), 렌즈 축소율 = 0.69·H·1.3/R_px|가장자리·내부 블러는 맞고, CoC ≫ 방울일 때 희미한 원판(②)보다 렌즈 윤곽이 더 남는다. 이웃 방울 보케 겹침 없음|추가 샘플 0, ALU ~10|낮음|
|**D-A 확률적 색 수집**|5×5에서 가까운 방울 ≤ 6개를 레지스터에 캐시 → CoC 원판 안 N개(Vogel 디스크, 픽셀·프레임 회전) 지점에서 선명한 WF 렌즈 색을 계산해 평균. CoC < 0.5 px이면 N = 1|N → ∞에서 정답(②). N = 4–6 + TAA/DLSS로 수렴|N × (장면 샘플 1 + ALU ~70). 오른쪽 근접 구역만 N > 1 → 예상 +0.1–0.25 ms|노이즈(DLSS 의존), 비용 변동|
|**D-B 오프스크린 층 + 가변 블러**|방울 층(색·알파 premultiplied)을 별도 캔버스에 그린 뒤 CoC 크기 mip/gather 블러 후 합성|정답에 가장 가깝고 결정적|전해상도 RGBA16F 1장 + mip + 합성 ≈ 0.15–0.3 ms|`render.mesh`를 `ExtraCanvas:update` 안에서 쓸 수 있는지 미확인(glass stack 순서도 바뀜)|

오프라인 결과: ③ D-C는 왼쪽(선명)과 경계·내부 블러에서 ②에 가깝고 모양·굴절을 유지한다(④의 실패 없음). 오른쪽 큰 CoC에서는 ②보다 렌즈 윤곽이 더 보인다.

## 5. 제안

1. **rev18 = WF 렌즈 + D-C + 거리 기반 CoC(A, zf)** 를 기본으로 한다. 추가 샘플 없이 결정적이고, 사용자 지적(모양 변형·굴절 소실)을 구조적으로 없앤다.
   기존 rev5 동공 평균 경로는 삭제한다.
2. 근접 구역(CoC > R)에서 D-C가 레퍼런스보다 렌즈처럼 남으면 **D-A를 그 구역에만** 켠다(`CoC/R > 1`일 때 N = 4). 전체 비용 증가는 오른쪽 일부 픽셀로 한정.
3. D-B는 `render.mesh` 오프스크린 가능 여부를 작은 실험으로 확인한 뒤 판단한다(필요 시 별도 단계).
4. 검증: Debug 6 = z(cm)와 CoC px 색 지도, 정지 상태 같은 방울에서 A·zf 변화 비교, 레퍼런스 B 좌·우 방울 선명도 비교.

## 6. 사용자 검토 결과와 수정된 결정 (2026-10-26)

1. **목표 = ② 정답 행**(선명하게 계산한 방울의 *색 층*을 CoC로 블러). ③ D-C는 근사로만 쓴다.
2. **거리 보정 불필요:** 실험 중인 kn5도 실제 형태대로 배치되어 왼쪽이 더 멀다. CSP 클리핑 실험에서 낮은 값에서는 화면 오른쪽부터, 높은 값에서는 왼쪽이 잘린다.
   따라서 `z = length(PosC)`(또는 행렬 계산)만으로 오른쪽 흐림·왼쪽 선명이 자연스럽게 나온다. 별도 좌우 보정은 넣지 않는다.

수정된 구현 순서:

- **1순위 D-B(오프스크린 방울 층 + 가변 CoC 블러):** ②와 같은 연산이고 결정적이다. 선행 실험 1개 — `ExtraCanvas:update(function() render.mesh(...) end)` 또는
  `render.backupRenderTarget()`/`restoreRenderTarget()` 사이에서 메쉬를 캔버스에 그릴 수 있는지, 깊이(하우징 가림) 처리가 가능한지.
  가능하면: 방울 층 premultiplied RGBA16F(반해상도) → CoC 크기 mip(또는 13-tap 원판 gather) → glass stack 같은 위치에서 합성.
- **2순위 D-A(확률적 색 수집):** D-B가 불가능할 때. 바이저 셰이더 안에서 같은 ② 결과에 수렴한다(N 4–6, DLSS 정리).
- **D-C:** 위 둘이 준비되기 전 임시 기본값, 또는 저사양 옵션.

## 7. rev18 결과와 rev19 결정 (2026-10-26)

- **D-B 불가:** 실험 버튼 결과 `render.mesh returned true, covered samples 0 / 9216`. `ExtraCanvas:update` 안의 `render.mesh`는 장면 카메라·깊이 없이
  아무것도 그리지 않는다. Lua 셰이더는 픽셀 셰이더 전용이라 정점 단계에서 UV 공간으로 펼칠 수도 없다 → 보류.
- **D-C 결함 수정:** 덮임 × (R/(R + c/2))²가 큰 방울까지 투명하게 만들었다(사용자 aperture 0/0.8 비교). 원판 ⊗ 원판의 중심값 min(1, (R/rb)²)로 교체.
- **D-A 구현(rev19 기본):** CoC > 1 px에서 4탭(Vogel, 픽셀·프레임 회전), 탭마다 선명한 WF 렌즈, premultiplied 평균. 상태 Load 25개는 공유
  (방울 캐시 대신 후보 루프 안에서 4개 누적기를 갱신 — 같은 효과, 동적 인덱싱 없음). D-C는 UI에서 끄면 쓰는 저비용 경로.
