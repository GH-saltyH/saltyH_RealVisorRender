# RainFX v2 — trail과 sheet를 하나의 얇은 물 규칙으로 (연구, 2026-11-13)
사용자 질문:
- trail과 sheet는 둘 다 표면의 비교적 평평한 물막이다.
- 통합 파이프라인에서 하나의 일관된 규칙으로 설명할 수 있는가?

도구: `docs/tools/rainfx2_film_unify_check.py`. 관련 문서: `RAINFX_V2_TRAIL_REVIEW2.md`, `RAINFX_V2_WATER_SHEET_PLAN.md` §2.

## 1. 현재 두 체계의 규칙 비교 (같은 표면, 다른 법칙)

|항목|trail (field R + TG)|sheet (field B)|방울(셀)|
|---|---|---|---|
|접촉각|trailThetaRDeg **28°**(후퇴)|sheetRecedeDeg **50°**(가장자리 각, 히스테리시스)|contactDeg **60°**(정적, 캡 부피)|
|생성|Ca > Ca\*(Cox–Voinov)|충돌 lamella, 방울 흡수, 핵생성(덮임 ≥ 0.5)|충돌, 분리|
|단면 / 가장자리|기울기 상한 0.45(24°) 고정|메니스커스 폭 h / tan θ, 전선 융기|구면 캡|
|안정성|고정, 증발 0.003 mm/s만(PL1 이후)|얇은 막(< hJoin): exp(−thinRate t) 소멸(질량 손실). 잔류 패치(≥ keep): 영구(증발만). 고립 패치 → 방울(W1t, 6 /s)|—|
|젖음|r2Wet: film + trail 깊이|r2WetTx: 공급 q ≥ wetFrac · q_c|—|
|흐름|핀 0.02 mm 초과분이 선을 따라|윤활 유량, Furmidge 핀 0.3 mm, 전선 0.22 mm|힘 균형|

- **같은 코팅 표면에 접촉각이 세 개(28 / 50 / 60°)**다. trail의 28°가 따로 떨어져 있어서 → 문턱 U\*가 5.7배 낮다(θ³) → 240 km/h에서 거의 모든 방울이 trail을 남긴다.
- **'영구 잔류'가 두 군데 있다:**
  - trail 선은 수 초–20 s 동안 막대로 남는다.
  - sheet 잔류 패치는 증발로만 줄어든다(W1k).
  - 둘 다 같은 물리(얇은 막의 비평형)를 무시한 결과다.
- 젖음 정의가 두 개라, 같은 곳이 trail에는 마른 면, sheet에는 젖은 면일 수 있다.

## 2. 통합 물리 (하나의 표면, 하나의 접촉선 법칙)
1. **평형:** 부분 젖음 표면에서 정지한 막이 평형이 되려면 두께가 퍼들 높이 e_c = 2 ℓc sin(θr/2)(ℓc 2.7 mm) 이상이어야 한다.
   - θr 28° → 1.3 mm, 50° → 2.3 mm. 바이저의 모든 trail / sheet(0.02–0.5 mm)는 그보다 얇다.
   - → **공급도 흐름도 없는 막은 존재할 수 없다.** 가장자리부터 후퇴한다.
2. **후퇴 속도:** V_d = (γ/μ) θr³ / (9 ln(W/λ)). trail 문턱을 정하는 Cox–Voinov 식 그대로다. 후퇴하는 테두리가 물을 모아 → Rayleigh–Plateau로 구슬이 된다(간격 ~4.5 W, 구슬 부피 = 간격 × 단면).
3. **수명:** 공급 없는 너비 W의 막은 t = W / (2 V_d)다. 같은 식이 선과 막에 다 적용되고, **크기만 다르다.**
4. **유지 조건(fed):** q ≥ h · 2 V_d / W. 지금의 W1g '피드' 규칙(q ≥ thinRate · hJoin)과 같은 꼴인데, 비율 thinRate가 상수가 아니라 2 V_d / W로 유도된다.
5. **흐르는 막:** 흐름 속도 > V_d면 막은 흐르면서 옆으로 2 V_d씩 줄어든다 → **rivulet으로 갈라진다**(유리창의 물 줄기). 위에서 공급받는 rivulet은 이력 창 안에서 고정되어 유지된다(Davis 1980).
6. **최종 형태:** 끊어진 물은 캡(방울 / 구슬)이 된다. 잔류 패치는 낮은 접촉각의 캡이고, 사용자가 W1k에서 원한 '남는 작은 덩어리'와 같다. 막 상태로 오래 남지 않는다.
7. **젖음:** 하나의 상태다. 후퇴하는 물이 남긴 얇은 층(Landau–Levich)이 θr을 낮추고 증발로 사라진다. trail과 sheet가 같은 값을 읽는다.

- **함의:**
  - trail 선은 ms 단위로 구슬이 된다(TR1과 같은 결론).
  - 잔류 패치는 수십 ms 안에 캡이 된다(W1t 비율 6 /s보다 빠름).
  - 흐르지 않고 공급 없는 sheet는 0.1–0.4 s 안에 rivulet / 구슬로 갈라진다.
  - 이것은 '추종 중 막이 덮였다가 공급이 줄면 줄기와 방울로 갈라지는' 레퍼런스 인상과 맞는 방향이다.
- **결정이 필요한 값:** 코팅의 θr 하나. V_d는 θr³에 비례하므로 이 값이 모든 수명을 정한다. 28 / 50 / 60°가 섞인 지금 상태를 하나로 맞추는 것이 출발점이다(레퍼런스로 검증: 정지 방울 각, 미끄러짐 시작 크기, 막이 갈라지는 시간).

## 4. 통합 파이프라인안
- **F0 표면 매개변수 통일:**
  - θs(정적, 캡 부피) 하나, θa / θr 한 쌍(히스테리시스), 젖음에 따른 θr 감소 하나.
  - trailThetaRDeg, sheetRecedeDeg, contactDeg / hysteresis를 이 값들에서 유도한다. 젖음 정의 하나(§2.7).
- **F1 공용 규칙 함수(common.hlsl):**
  - r2RecedeAngle(wet), r2DewetSpeed(W, wet), r2FedRate(W, wet) = 2 V_d / W, r2BeadRow(W, 단면) → (간격, 구슬 r).
  - trail / sheet / bead / visor가 모두 이 함수만 쓴다.
- **F2 trail = 좁은 막:** TR1(끊어짐 = t_b = hw / V_d, 대개 < 1프레임), TR2b(구슬 줄 그리기, r2BeadRow), TR3(새 꼬리만 선)을 F1으로 구현.
- **F3 sheet 가장자리:**
  - 공급 없는 막은 가장자리 후퇴 = 가장자리 텍셀의 물을 안쪽 테두리로 옮긴다(질량 보존, 프레임당 V_d dt ≈ 0.2–1.7 텍셀).
  - 테두리가 두꺼워지면 bead 패스(W1t)가 캡으로 만든다.
  - 흐르는 막은 같은 후퇴가 옆으로 작동해 rivulet으로 좁아진다.
  - W1k 영구 잔류와 thinRate 상수 소멸(질량 손실)을 이것으로 대체한다.
- **F4 (선택) 표현 통합:** field R(선 깊이)을 B로 합치고, TG는 'B의 서브텍셀 선 기술자'(폭 < 텍셀일 때)로 둔다. 물 장부가 하나가 된다. F2–F3 뒤에 평가한다.
- 비용:
  - F0–F2: 함수 치환, visor 구슬 2–3개 → +0.01–0.03 ms.
  - F3: 가장자리 판정 + 인접 이동, 기존 sheet / field 패스 안 → +0.01–0.03 ms.
  - 새 패스 없음.

## 5. 위험과 확인 항목
1. **θr 선택이 모든 것을 바꾼다**(θr³). 50°면 trail 문턱이 5.7배 높아진다 → 240 km/h에서도 r ≲ 0.5 mm는 trail이 없다. 막은 매우 빨리 갈라진다. 레퍼런스 확인이 먼저다.
2. 흐름이 없는 정지 상태의 넓은 막(정지 시 crown 유출)은 젖은 면 / 공급 조건에서만 남는다. 정지 장면 레퍼런스와 맞는지 확인한다.
3. F3 가장자리 이동은 프레임당 텍셀 1개 이상이다(빠름). 한 프레임 튐(사용자 기준)이 없도록 테두리 렌즈의 연속성(P2 메니스커스)을 함께 확인한다.
4. 구슬 줄 / 캡의 이동성: 그린 구슬은 정지해 있다. 셀 방울로 넘길 크기 경계(a_max 또는 움직임 문턱)를 정한다.

## 7. 배수 흐름 (사용자, 2026-11-13)
사용자 관찰과 방향:
- 지금 sheet는 흐르기보다 그 자리에 생긴 뒤 그 자리에서 쪼그라들며 사라진다.
- 이상적인 모습: trail과 sheet 모두 전체 운동 방향으로 모여 흐르며 배수된다. 그 사이 일부가 남아 방울이 되는 것은 타당하다.

### 7.1 진단 (`rainfx2_film_unify_check.py` 부록, 외부 공기 = 차 속도, Cf 0.005, 경사 30°, θr / θa 50 / 70°)

|속도|공기 τ|막 속도 h 0.02 / 0.05 / 0.1 / 0.3 mm|움직이기 시작하는 길이 L_c (Furmidge)|
|---|---|---|---|
|정지|0|0.001 / 0.004 / 0.016 / 0.15 m/s|221 / 88 / 44 / 15 mm|
|110 km/h|2.8 Pa|0.03 / 0.07 / 0.16 / 0.57 m/s|5–7.5 mm|
|240 km/h|13 Pa|0.13 / 0.34 / 0.68 / 2.1 m/s|~1.6 mm|

- **D1 두께 기준 고정:**
  - 고립 패치는 sheetPinMM 0.3 mm 아래 물 전체가 고정된다(hRes) → 0.3 mm보다 얇은 패치는 속도와 상관없이 움직이지 않는다.
  - 물리(Furmidge)는 길이 기준이다. (τ + ρ g h sinα) L ≥ γ (cos θr − cos θa).
  - 240 km/h에서는 1.6 mm 넘는 물이 모두 움직이고, 정지 시에는 수십 mm 덩어리만 중력으로 움직인다.
- **D2 수송 속도 상한:**
  - 유량 갱신은 텍셀당 Courant 0.24 / substep으로 묶여 있다(8 substep, 60 fps, 텍셀 0.59 mm → **최대 0.068 m/s**).
  - 물리 막 속도(240 km/h 0.13–0.7 m/s)보다 2–10배 느리다. 같은 장면의 방울은 0.35–0.77 m/s다 → 막만 제자리에 있는 것처럼 보인다.
- **D3 제자리 소멸:** 작은 Courant의 업윈드 수치 확산(퍼지며 얇아짐) + 얇은 막의 thinRate 지수 소멸(질량 손실) → '쪼그라들며 사라짐'.
- **D4 생성 위치:** lamella 스탬프가 충돌점에 패치를 놓는다(팝업). 고속에서는 그 물이 곧바로 하류로 실려 가야 한다(D1 / D2 때문에 못 감).
- **D5 trail:** 선은 고정되어 있다(핀 0.02 mm 초과분만, runbackMax 0.06 m/s까지 자기 선을 따라 흐름). 끊어짐 규칙도 없다(TR 참조).

### 7.2 통합 규칙 F5 (배수)
1. **이동 여부(모든 막, 선 공통):** 길이 기준 Furmidge. L_c = γ Δcos θ / (τ + ρ g_t h)(Lua에서 프레임마다 계산).
   - 물 덩어리의 흐름 방향 길이 ≥ L_c면 전체가 움직인다. 길이는 연결 막 창 / 선 길이 / 패치 크기에서 가져온다.
   - 정지 시 작은 패치와 선은 그대로, 고속에서는 거의 모두 움직인다.
2. **수송:** 질량 보존을 유지하면서 Courant > 1을 허용하는 플럭스형 semi-Lagrangian(FFSL, Lin & Rood 1996: 정수 칸 이동 + 소수 부분 업윈드).
   - 속도 상한이 물리값(≤ 공기 / 중력 법칙, 방울 속도와 같은 크기)이 된다.
   - substep 수는 CFL이 아니라 정확도 기준으로 줄일 수 있다(8 → 2–4).
3. **수렴:** 흐르는 막은 옆으로 2 V_d씩 좁아지며(§2.5) 두꺼운 흐름으로 모인다(W1r 배수 수렴 유지) → 하류 방향 rivulet. 바이저 가장자리(마스크 밖)로 나간 물은 사라진다(배수).
4. **남는 물:** 흐름 뒤에 남는 것은 F1 규칙(후퇴, R–P)으로 구슬 / 방울이 된다.
   - 구슬 크기 ≥ 움직임 문턱(그 속도의 depin 반경) → 셀 방울(달린다).
   - 더 작으면 그려진 구슬(TR2b) 또는 미세 층.
   - thinRate 소멸(질량 손실)과 영구 잔류는 없앤다.
5. **trail:** 머리 뒤 선은 F1 / TR로 구슬이 된다. 같은 길을 반복해서 흐르는 물(공급받는 선)은 F5-1 / 2로 흐르는 rivulet이 된다. → 모든 물이 같은 방향으로 모여 흘러 나가는 인상.

### 7.3 기대 모습
- **240 km/h 추종:** 막은 생긴 자리에서 0.13–0.7 m/s로 하류로 쓸려 가며 줄기로 모이고, 바이저 높이(~150 mm)를 0.2–1.1 s에 지나 가장자리로 빠진다. 지나간 자리에는 작은 방울과 미세 조각이 남는다.
- **저속 / 정지:** 얇은 패치와 선은 그 자리에서 구슬이 되고, 두꺼운 흐름만 중력으로 천천히 내려간다(지금 정지 장면과 같은 성격).
- 비용:
  - FFSL 갱신은 기존 4방향 유량과 비슷한 Load 수다. substep을 줄이면 비용은 같거나 줄어든다.
  - 길이 판정은 기존 연결 막 마스크(nuc) 재사용.
  - 예상 순증 0–0.03 ms.

## 8. P0 프로토타입 (`docs/prototypes/rainfx2_film_drain_proto.py`, 그림 `rainfx2_film_drain_240.png`, `_0.png`)
- 통제 장면(공급 모델은 시험 대상이 아님):
  - 60×40 mm, field 텍셀 0.59 mm, 60 fps.
  - t = 0에 sheet 패치 3개(W 4 / 10 / 20 mm, h 0.06–0.15)와 달리는 방울 14개(r 0.3–1.0)를 둔다.
  - 왼쪽 15 mm는 공급 띠(240 km/h: 분무 1 mm/s = 극단 플룸, 정지: crown 유출 0.2 mm/s), 빗방울 잔류 캡은 충돌 비율로 생긴다.
- 행은 현재(근사: 0.3 mm 두께 고정, 0.068 m/s 상한, 얇은 막 지수 소멸, 막대 trail)와 통합 θr 28 / 40 / 50°, 열은 t 0.02 / 0.08 / 0.25 / 1.0 s다.
- **240 km/h:**
  - 현재: 패치가 그 자리에 옅은 판으로 남고(필름 58 → 178 mm³ 누적), 공급 띠가 막대 다발이 된다.
  - 통합: 패치는 0.02–0.08 s 안에 하류로 쓸려 나간다(배수 1 s 동안 공급의 ~96 %). 공급 띠는 하류로 흐르는 줄기가 되고, 그 가장자리에서 구슬이 떨어져 나와 달린다.
  - θr이 클수록 막은 줄고 구슬은 늘어난다(1 s 뒤 캡 1.7 / 14 / 19 mm³).
- **정지:**
  - 현재: 패치가 오래 남고 막대 trail.
  - 통합 θr 28°: 10 / 20 mm 패치가 0.08 s까지 막으로 남은 뒤 구슬이 된다. 40 / 50°는 0.02–0.08 s 안에 구슬. 공급 띠는 중력으로 내려가며 줄기와 구슬이 된다.
- **프로토타입 한계(게임 구현에서 다르게 할 것):**
  - 구슬이 텍셀 격자처럼 줄지어 보이는 것은 텍셀 침식 근사의 인공물이다. 게임에서는 R–P 간격 + 지터(r2BeadRow)로 둔다.
  - 두꺼운 공급 띠가 어둡게 보이는 것은 2D 렌즈 대용의 기울기 처리 때문이다.
  - 캡끼리의 병합은 넣지 않았다(캡이 막에 닿으면 합류만).
- **결론:**
  - 길이 기준 이동 + 상한 없는 수송 + 공용 후퇴 규칙만으로 '생기고 → 흐르고 → 모이고 → 빠지고 → 일부만 방울로 남는' 그림이 나온다.
  - 현재의 '제자리 팝업 → 쪼그라듦'과 막대는 D1–D5에서 나온다는 것을 확인했다.
  - θr은 수명과 구슬 양을 크게 바꾼다 → 레퍼런스(정지 시 lamella 패치가 구슬이 되기까지의 시간, 고속에서 막 줄기 가장자리의 구슬 양)로 정한다.

## 9. 표현 방식 (사용자 질문: trail과 sheet 모두 높이 지도로 유체 흐름을 만드는가)
- **질량, 흐름, 규칙은 하나의 높이 지도 h(field B)다(F4).**
  - 평평한 물(충돌 패치, sheet, 공급받는 rivulet, 머리가 남긴 trail 물)은 모두 h에 들어간다.
  - 같은 수송(윤활 유량, FFSL), 같은 이동 판정(Furmidge 길이), 같은 후퇴 / 구슬 규칙, 같은 배수(가장자리 유출)를 받는다.
  - trail이 sheet에 닿으면 자동으로 합쳐진다. 방울은 h의 물길을 따라간다(trailFollow / sheetFollow가 h 하나를 읽음).
- **모양(그리기)은 폭에 따라 다르다:** field 텍셀은 0.59 mm인데 trail 선은 폭 0.12–0.5 mm라 높이 지도로는 모양을 담을 수 없다(수송하면 텍셀 폭으로 퍼짐).

|폭|무엇|모양 정보|
|---|---|---|
|≥ 2 텍셀(~1.2 mm)|sheet, 패치, 넓은 rivulet|h의 B-spline 등고선(P2 메니스커스, 서브텍셀 가장자리)|
|< 2 텍셀|새 trail 꼬리, 가는 rivulet, 구슬 줄|선 기술자 TG(점, 방향, 반폭) = h의 서브텍셀 보조 정보. 물 양은 h에 있다|
|캡|방울, 구슬(움직이는 크기 이상)|셀 엔터티(지금 그대로)|

- **실제로 흐르는 trail:** 머리 뒤 선은 대부분 ms 안에 구슬이 되므로 흐르지 않는다. 흐르는 것은 위에서 공급받는 rivulet뿐이고, 그것이 h의 흐름이다. 공급이 커져 폭이 2 텍셀을 넘으면 등고선 표현으로 자연스럽게 넘어간다(같은 h이므로 전이 튐이 없다).
- **대안:** field 해상도를 2배(0.29 mm, haze와 같음)로 올린다.
  - 가는 rivulet까지 높이 지도만으로 그릴 수 있다.
  - 대신 흐름 비용이 4배(텍셀 수)다. substep을 줄이는 FFSL로 일부 상쇄되지만 0.2 ms 지침을 넘을 가능성이 있다 → 기술자 방식이 우선.
