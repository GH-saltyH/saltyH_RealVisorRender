# 가는 트레일 표시 복원 — 첫 구현과 채택 판단

2026-10-25. **Python 표시 후보와 재사용 HLSL helper 구현 완료. 게임 적용은 하지 않았다.**
이 단계는 실제 장면 품질 통과나 전체 RainFX 완성을 뜻하지 않는다.

## 구현 범위

앞 단계와 동일한 실제 KN5, 캡처 방울128개, 초기 속도0, 건조 field에서1초를
진행했다. 현재 bare/coat 재질과105°/8° 가설의 캡처 힘 조건을 표시 비교한다.
전체6조건 native trace도 재실행하여, **실제로 방울에서 차감한 물량과 이전/현재
위치, 물리 접촉 폭**을 step별로 저장한다. 기존 결과 폴더는 덮어쓰지 않는다.

표시 gain .31748은 폭을 정하는 표시 복원에서만 사용한다. 물리 힘, 직경, 질량,
방울 경로 또는 전달 물량을 바꾸지 않는다. 표시 폭을 좁히면서 같은 물량을
유지하므로 복원한 높이가 커진다. 이것은 미측정인 실제 미세 수막 형상의 증명이 아니다.

구현한 비교는 다음 네 가지다.

1. 기존1024×256 Gaussian capsule CPU 근사.
2. 선분 위치와 좁은 폭으로4096×1024 표시 높이를 복원. 기존 deposit을 **대체**한다.
3. 2번을 기존 각 셀의 물량으로 정규화. 세부 정보가 없는 셀은 균일 분배한다.
4. 선분에서 높이와 기울기를 직접 구하는 연속 Gaussian capsule. 거친 높이
   텍스처를 다시 미분하지 않는다. HLSL helper도 추가했다.

2번은 전역 물량+경계 유출을 보존하지만 셀별 재고가 달라진다. 3번은 셀별 재고를
보존하지만 거친 격자의 흔적과 가정한 형상은 남는다. 4번의 연속 평면 적분은
정규화되어 있으나 이산 샘플·경계 mask·3σ 절단 후 완전히 같은 물량은 아니다.
어느 후보도 현재 누적 수막 위에 중복 합성하지 않는다.

|---|---:|---:|---:|---:|
|현재 bare/coat|.514899|4.063|18.692|19.984|
|105°/8° 가설|.420374|3.616|12.694|13.661|

좁은 표시와 기존 field의 같은 셀 물량 겹침은 각각69.4%,76.4%다.
따라서 단순히 폭을 줄인 그림을 현재 수막 원장과 동일하다고 취급할 수 없다.
셀 보존 후보의 최대 셀 잔차는2.2e-19mm³ 이하였다. 이는 float64 표시 도구의
결과이며 CSP 원장을 통과했다는 뜻이 아니다.

연속 helper의 이산 표시 적분은 현재 재질에서.514970mm³로 전달량보다 약.014%
높다. 이것을 새 물로 원장에 반영하지 않는다. 이 helper는 표시 전용이다.
두 경우 모두 이 짧은 장면에서1mm 이상 고임은 없다. 이전 수송 후보의 큰 고임을
해결한 결과는 아니며 초기 field가 건조하다는 차이가 중요하다.

## 이미지 판정: 일부 정보 복원, 품질 통과 아님

`captured_current_motion/optics_comparison.png`의 순서는 왼쪽 위부터 기존 격자,
좁은 선분, 셀 보존, 연속 기울기다. 실제 물량의 가는 굴절은 더 잘 보이지만
**끊김/울퉁불퉁함이 여전히 남는다.** 선분별 끝부분의 겹침과 표시 샘플링, 실제
경로/물량 변화가 함께 기여할 수 있다. 이 비교만으로 각 원인의 비중을 확정하지 않는다.
단순 해상도 상승이나 직접 기울기만으로 문제가 해결됐다고 하지 않는다.

이미지는 동일한 합성 배경과 UV 현미경 배율이다. 게임 카메라, E2/E3 레이어,
HDR 또는 완전한 impact/birth 장면을 재현한 영상이 아니다. 각 재질의 ROI는 그
재질의 최대 deposit 부근이며 서로 다른 재질의 같은 위치 비교로 해석하지 않는다.

## 비용과 다음 제품 연결 경계

4096×1024 R32F는16MiB, 두 장은32MiB다. 높이/기울기 여러 채널과 이력까지
보관하면 더 늘어난다. 해상도4배/축은 픽셀16배이며 무조건 저비용이라고 할 수 없다.
`rainTrailCapsule.hlsl`은 정규화 거리, sqrt, exp를 쓰며 텍스처 fetch 자체는 없다.
그러나 이를 전체 화면에서 모든 방울에 반복하는 구현은 채택하지 않는다.

**채택하지 않은 것:** 전체 물리 field 확대, 물리 직경 확대, 기존 수막 위에
detail 추가, 재질 가설 자동 적용. 게임 실행 패스·GPU 자원·기본값은 그대로다.

다음 연결에서는 새 deposit의 표시 이력을 유한하게 보관하고, 같은 물을 coarse
수막과 detail 양쪽에 표현하지 않도록 해야 한다. 연속 경로의 겹침/샘플링을 먼저
해결할 작은 표시 범위를 선택한다. 전체 물리 재계산이나 새 probe 시리즈를
선행 조건으로 만들지 않는다.32Hz 표시 보간과 실제 C/B/A 장면 평가는 미완료다.

## 검증과 재현

- `run_material_trajectories.py --output docs/diagnostics/2026-10-25/subcell_trails/trajectories`
  : 실제 motion/trace 재사용,6조건204 WARP draws, 물량 원장 확인.
- `review_subcell_trails.py`: 두 조건의 transfer/셀 보존 및 네 표시 방식 비교.
- `check_trail_capsule.py`: 실제 선분과 길이0/물량0을 포함98개 입력,
  native WARP1 draw/1 program, CPU 대비 검증 통과.
- 최초 HLSL 컴파일에서 예약어 `point`를 사용한 오류는 `uvPoint`로 수정했다.
  최초 보고서 저장의 NumPy 정수 직렬화 오류도 수정했다. 실패를 성공 실행으로 세지 않는다.
- 실제 CSP 실행/새 사용자 시험 요청0회. Python/소프트웨어 GPU 시간은 게임 FPS가 아니다.
