## 원인1: 내가 추가한 표시 합성의 셀 경계

이전 compose는1024×256의 정규화 계수를 `Load(p>>2)`로 읽어, 동일 값을
4096×1024의4×4 픽셀에 반복했다. 기존 셀 평균 높이가 불연속인 계단 표면이 된다.
최종 유리 셰이더는 그 값을 fine 간격으로 미분하므로 경계에서 강한 굴절이 생긴다.
해상도만 늘리고 셀별 표시 물량 일치를 확인한 것으로는 이 표면 연속성을 보장할 수 없었다.
짧은 건조 장면만으로 품질을 판단한 검증 범위도 부족했다.

실제 보존된12343 film/micro의 두꺼운 재고로 같은 compose를 재현했다. 이것은
이번 영상의 정확한 새 재고가 아니라, **건조1초가 아닌 실제 누적 재고**의 별도 대조군이다.
film20,481.524mm³와 micro1,217.448mm³, 같은 head·광학 조건을 유지했다.

기존 point 확대는 유효 영역의 높이 변화가 거의 전부 coarse 셀 경계에 집중됐다.
이것은 실제 영상의 모든 원형 패턴이 표시 버그라는 뜻은 아니지만, 격자 찢김을
만들 수 있는 구체적인 코드 결함을 확인한 것이다.

## 적용한 수정

coarse 광학 계수에 양의 cubic B-spline 재구성을 적용했다. 같은 입력을 사용하는
4회 bilinear fetch 방식이며 추가 pass/texture는 없다. 고해상도 density는 유지한다.
유효한 support는 중간 A채널에 기록하고, target이 invalid이면0으로 유지한다.
유효하지 않은 이웃은 필터의 support weight로 정규화한다. 서로 다른 UV island가
직접 맞닿아 있는 경우까지 완전한 기하 기반 필터라고 주장하지 않는다.

방법의 원전: [NVIDIA GPU Gems2, Fast Third-Order Texture Filtering](https://developer.nvidia.com/gpugems/gpugems2/part-iii-high-quality-rendering/chapter-20-fast-third-order-texture-filtering).

물리 stock과 전달량, source/시간 검사,1024×256 물리 격자는 바꾸지 않는다.
필터 전 coarse/detail 예산 검사는 유지한다. 필터 후 화면의 각 셀 적분까지
원래 cell volume과 정확히 같도록 강제하지 않는다. 화면 필터는 물리 수송이나
물량 생성/증발이 아니며 결과를 solver에 되먹임하지 않는다.

native flooded 대조군의 결과:

|표시|기존 셀 경계에 집중한 높이 변화|인접 fine pixel 최대 높이 변화|
|---|---:|---:|
|point4×4 확대|약100%|3648µm|
|연속 표면 재구성|약25.2%|485µm|

`flooded_before_after.png`는 같은 물량/배경의 전후 비교다. 격자 패턴은 약해지지만
**큰 고임과 넓은 굴절은 남는다.** 실제 CSP에서 수정된 화면을 확인한 결과는 아직 없다.
4회 bilinear 읽기+support 확인으로 compose의 texture fetch는 늘지만,
전체 재구성12드로우/102MiB는 그대로다. 실제 GPU 시간은 별도 미측정이다.

## 원인2: 지속 고임을 해결하지 못하는 현재 물리 범위

현재 제품은 head 운동·deposit·field 증발/micro 합류만 수행하며, film 자체는
제자리에 고정된다. 능동 film 이동/배수, 고임의 head 반환·흡수는 빠져 있다.
직접 충돌로 field에 배분된 물과 오래된 trail 물이 쌓이며, 최근.5초 detail 이력이
끝나도 그 물은 coarse 수막에 남는다. 이 정책 자체가 재고를 지키지만, 지속적인
공급 하에서 현실적인 정상상태를 만들지는 못한다.

그러므로 이번 넓은 패턴의 지속을 정상적인 visor 수막으로 승인할 수 없다.
현재 영상의 구체적인 원형 크기별 source 기여율이나 실제 새 수막 높이는 아직
측정하지 않았다. 하지만 **정적인 film+증발만으로는 필요한 배수/고임 반응이
없다는 구조적 결함**은 코드로 확인된다. source ledger 통과와 시각적 타당성은 다르다.

물을 지우거나 증발률을 임의로 키워 가리지 않는다. 과거 donor-cell 후보는 거대한
고임을 만들었으므로 검증 없이 다시 켜지 않는다. 기존 P4b도 현 제품에서 꺼져 있고
단일 cell 반환/빈 슬롯 의존을 갖는다. 과거에 일부 게임 검증을 통과했다는 이유만으로
장기간 visor 장면까지 해결한다고 가정하지 않는다.

## 다음 필수 작업의 변경

후속 영상에서 트레일은 관찰되지만32Hz 위치 교체가 직접적인 품질 문제로 지적됐다.
[표시 보간](RAINFX_FRAME_DISPLAY_INTERPOLATION.md)을 한 가지 접근으로 연결해 이 결함을
분리했다. 게임 품질 통과는 아직 아니다. 다음 필수 작업은 **bulk 고임/배수의 물리 처리와
약한 비의 dry-start 일관성**이며, 보간으로 넓은 수막 결함을 해결했다고 하지 않는다.
다음 구현은 물리량과 출구/재부착을 설명할 수 있는 bounded 모델 한 가지로 한정한다.
과거 source/ABI 정밀도 probe 시리즈를 다시 선행 조건으로 만들지 않는다.

이번 격자 수정만으로 정상 수막 흐름이 완성됐다고 하지 않는다. 추가 장시간 사용자
시험을 지금 요청하지 않는다. 기존 영상과 보존 재고를 사용해 다음 모델을 평가한다.

검증: 수정 소비 shader10 WARP draws, 실제 flooded compose2 draws,
제품 회귀13그룹 통과. shader 숫자 검사는 화면 품질 불합격 판정을 뒤집지 않는다.
첫 두 filter 검사는 이상적64-bit 결과의 비트에 가까운 일치/단순 sampler 모형이
부적절해 실패했다. sampler 모형 추적을 더 확대하지 않고 화면 필터의 유한 정밀도
범위로 검사를 분리했다. 물리 예산 검사는 동일하게 유지했다.

Direct3D texture addressing/filter 정밀도 참고:
[Microsoft D3D11.3 specification](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm).
이 규격을 실제 CSP 버그나 특정 GPU의 exact 수치 원인 증명으로 쓰지는 않는다.
