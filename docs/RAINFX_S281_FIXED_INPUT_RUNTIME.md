## Nonlinear input choice and why

The initial simpler draft used a coherent midpoint source. That avoids averaging
unrelated density/wind/DSD fields, but a rain-density change within a step could
still bias expected supplied encounters. It was replaced before game testing by
one density-time-weighted reservoir sample, reusing the stochastic nature of the
existing birth model. This is the second and final approach for this stage.

For captured pieces i with density n_i and duration dt_i, retain
D=sum(n_i*dt_i). Reservoir choice has probability n_i*dt_i/D. Pass effective
density D/modelDt plus that chosen sample's DSD weights and incident air vector.
For fixed endpoint geometry N and random sampling, expectation is
D*E[p_bin(source)*max(-relative(source,bin) dot N,0)], equal to the temporal sum
of those nonlinear encountered-bin rates. No per-site CPU loop or extra GPU pass.
Water conservation still refers to the source events actually generated by the
existing GPU model, not to an independently asserted CPU incident-water total.

This does NOT make the whole nonlinear motion or changing geometry integral exact.
The geometry is evaluated at the rigid endpoint; SI/film airflow uses the coherent
midpoint weather sample. Rapid orientation, depinning and air-force changes within
31.25ms remain a game-simulation approximation requiring the later visual gate.
Steady weather does not gain artificial temporal-source variance because chosen
samples have the same physical source values.

Inertia and effective body-acceleration coefficients integrate over all captured
pieces. The already evaluated evaporation coefficient integrates likewise. Divide
these integrals by represented solver dt so rounding does not silently discard
impulse. Wind vectors themselves are not averaged and reinterpreted as nonlinear
drag. Material/calibration changes, frame/time inconsistency and scale edits
refuse rather than blend incompatible states. Display gain is not a rate channel.

## Runtime contracts retained

Use the same128 canvas descriptors, fixed stock selection and receipt namespace;
no GPU shader/body changes. Simulation input capture runs at renderer cadence,
while normal solver submissions are32/s. Existing per-step readback still exists;
reducing its diagnostic role and adding a GPU-side coherent optical commit
consumer remain outstanding. The source/allocation/force graphs are reused.

The owner retires completed work before intake and advances accepted physical
time only after its ordered receipt. Startup compilation precedes live capture.
No three-second stop: run until explicit stop, overload, input reset or refusal.
A long frame can create several physical tickets; stop seals a represented tail.
Subtick input remains reported. Unadmitted overload input is retained/reported;
there is no hidden frame/time discard or automatic claim to recover lost samples.
On fault the existing owned resources remain retained; a caller must later route
to fallback. No generic completion fence or public optical texture is exposed.

## Focused local verification

One product checker uses the actual bootstrap/capture/composer, actual cohort
validation and actual owned-executor state machine with mocked engine APIs and GPU backend.
Eight groups cover typed density/DSD/wind correlation, signed impulse, rigid pose,
30/60FPS,200ms frame, pauses, GPU rejection and scale-reset handling.
At30/60FPS and the long-frame/pause cases,1s captured time produces32 accepted
steps and zero debt on explicit stop. All use128 descriptors and20 runtime file
checks. Refusal/reset cases stop and retain debt. This is not actual GPU physics.

The existing11 s280 cadence groups were reused on v2, not expanded into a new
matrix. Three local checker invocations passed (product, reused cadence, product
again after private-seed ownership hardening). No user game run, GPU probe or
shader recompilation was requested. An unchanged numerical core does not need a
new precision qualification suite merely because its input cadence changed.
