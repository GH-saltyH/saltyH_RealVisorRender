# RainFX 제품 목표 복귀와 개발 방식 재평가

현재 코드 진행: [기본 deposit+drying 경로](RAINFX_PRODUCT_DEPOSIT_BASELINE.md)가
같은 P0 프리뷰에서 능동 film 수송을 제외한다. 물리 방울과 연결된 물길·마름을 남기며,
frame 표시의 부드러움과 시각 배율은 아직 구현 과제로 남는다. 실제 CSP는 미검증이다.

환경별 최종 화면은 [사용자 영상 세 장면](RAINFX_TARGET_SCENES.md)을 기준으로 한다.
같은 통합 경로에서 C(낮은 공급)→B(부분 haze/선명한 길)→A(큰 공급/강한 굴절)를
확인한다. 세 개의 하드코딩된 날씨 preset이나 새 독립 probe로 대체하지 않는다.

첫 구현 상태: [field 마름/micro 전환](RAINFX_PRODUCT_FIELD_LIFECYCLE.md)을 기존
통합 경로에 연결했다. 실제 셰이더·원장·cache 로컬 검증을 통과했으며 CSP는 미검증이다.
이것은 최소 실행기 전체 단순화의 완료가 아니고,32Hz 표시와 배율 문제도 아직 남는다.

2026-10-25. **현재 개발 우선순위 문서.** 초기 목표는 유지하되, 이전 로드맵의
추가 연구·엄격 승인·선택 기능 선행 조건보다 이 문서의 제품 순서를 우선한다.
이번 산출물은 소급 평가와 범위 재설정이다. 런타임을 단순화하거나 게임 성능을
개선했다는 뜻이 아니다. 기존 코드·실패·Git 이력은 보존한다.

프리뷰별 실제 연결과 빠진 기능은 [시각 평가 계약](RAINFX_PREVIEW_VISUAL_CONTRACT.md)을
따른다. 후속 코드 감사에서 현재 s282에 예전 P3의 field 증발/micro→film 전환이
연결되지 않은 것을 확인했다. 다음 최소 경로의 필수 복구 항목이며,32Hz 위치 보간
부재와 head-only 표시 축소도 최종 품질로 받아들이지 않는다. 물리 모델은 재사용한다.

## 1. 처음 요청한 제품

근거: s73 설계와 s74 사용자 범위 조정.

- 실제 CSP 강수·풍속·차량 운동·습도 등의 신호로 유입과 마름을 구분한다.
  트랙 wetness/water를 바이저 물 재고로 직접 대입하지 않는다.
- 물리 부피·질량·접촉 크기로 고착/이동/충돌/물길을 일관되게 계산한다.
  표현 크기 계수는 물리 수치에 반영하지 않는다.6px/mm는 UV 교정이지 화면 px가 아니다.
- 방울·trail/rivulet/sheet·micro가 화면에서 연결되고 굴절하며, 정차와 주행 모두
  납득 가능한 하나의 효과로 보인다. 물을 더한 보정 레이어로 문제를 덮지 않는다.
- Smear와 legacy local impact film은 기본 모델에서 제외한다.
- 게임에 맞는 비용과 단순한 GPU 갱신을 우선하고, 관측되지 않은 대기/재질 값은
  근사로 취급한다. 전면 유체 해석은 목표가 아니었다.

특히 s73 §10/s74 §3은 **deposit·증발·배수와 기본 화면 평가를 먼저**, 능동 수막
수송·흡수는 필요할 때 추가하도록 했다. 완전한 수송/원장/승인 체계를 기본 장면의
선행 조건으로 만든 것은 이 순서에서 벗어난 결정이었다.

## 2. 성과와 미달을 함께 판정

|영역|남길 성과|제품 목표 기준 판정|
|---|---|---|
|입력·단위·물리 크기|실제 엔진 입력, SI 운동, 표시 gain 분리의 사용자 관찰|재사용 가치가 높음|
|P1/P2/P3|실제 날씨·주행 로그, 생성/운동/film 화면 및 FPS 관찰|독립 시험 이상의 실제 증거는 있음. 최종 통합 품질 통과는 아님|
|곡면·수송·GPU 전달|일부 단위/경계/API 오류와 복사·저장 비용을 발견|모든 세부 연구가 제품에 필요했다는 근거는 없음|
|s282|실제 입력과 광학에 연결되어 사용자에게 수분간 물방울·수막 출력|실장면에 전혀 접근하지 않은 상태는 아님. 안정적인 대표 장면 평가와 채택에 실패|
|전체 결과|많은 검사 통과와 부분 재사용 코드|사용 가능한 완성된 RainFX, 일관된 화면 품질,2048/4096 전체 비용이라는 목표는 미달|

따라서 **투자 대비 제품 성과는 실패에 가깝다**는 평가를 수용한다. 현재까지의
실패가 단위 계산·보존 개념 전체의 무용함을 증명하지는 않지만, 이미 쓴 노력을
이유로 복잡한 실행 구조를 계속 완성해야 한다는 결론도 성립하지 않는다.

## 3. 어디에 과도한 비용과 기준이 들어갔는가

1. **선택 사항의 필수화:** P4 수송/고임 반환, 정밀한 곡면 재배치와 원장 검증이
   기본 시각 효과보다 먼저 진행됐다. 빠르게 움직이는 persistent drops와 deposit
   경로만으로 충분한지 먼저 검증할 기회를 놓쳤다.
2. **검사기의 제품 경로화:** 매 구간 승인·원장·readback·시간 ticket·다중 commit이
   실제 실행과 결합됐다. 일부 수치 판정/국소 한도가 전체 FX를 끈다. 단순히 로깅을
   끄거나 허용오차 하나를 바꾸는 것으로 이 의존성이 제거되지는 않는다.
3. **통합보다 국소 통과 최적화:** 고정된 임시 입력, FP32 재현성, 헤더·부분 그래프의
   성공을 다음 연구의 근거로 삼았지만, 같은 실제 장면의 완성도·frame ms와 연결하는
   주기가 너무 길었다. s229/s279의 방향 수정도 런타임 구조에 충분히 반영되지 않았다.
4. **실패 범위 과대:** 방울 하나의 제한된 이동이나 작은 수치 잔차가 전역 중단으로
   확대됐다. 반면 실제 자원 오용/NaN/대량 물 복제는 계속 엄격히 막아야 한다.
5. **진척·추정의 과대 해석:** 단계 번호·검사 수·draw 절감은 제품 완성률이 아니다.
   s282–s283의 과거2.75–6h 추정은 불확실한 통합 비용을 반영하지 못했다. 폐기한다.

전체 과거 연구 시간을 신뢰성 있게 합산할 기록은 없다. s번호를 실행 횟수나 시간으로
환산하지 않는다. 현재101 prototype 폴더/13 probe 폴더도 성공 실험 수를 의미하지 않는다.

## 4. 현재 비용의 확인 가능한 하한과 한계

기존 실제4592 입력의4096-head,31.25ms 반복 recipe를 **GPU 실행 없이** 재구성했다.
증거: `diagnostics/2026-10-25/product_refocus/static_cost.json`.

|항목|현재 정적 구조|
|---|---|
|solver 반복 제출|109 draws + audit1 /32Hz 구간 =3520 draws/s|
|선택 film 수송|force/velocity/flux/gather 각8회, 합32 draws/구간|
|source transaction|19 passes + 별도 source guard|
|그래프 canvas|96개, descriptor 약132.69MiB|
|audit 슬롯|32개 추가. 실제 사용자 표시128 resources와 구분|
|읽기 전용 이미지|descriptor 약40.13MiB|
|추가 광학|위 수치에서 제외. snapshot4draws/렌더프레임 및 기존 raster/optics 등이 더 있음|

이 수치는 GPU ms, 실메모리 할당, 최종 FPS가 아니다. 모든 pass를 측정 도구로
분류하거나 전부 삭제할 수 없다. 상태·수송·선택·검사가 섞여 있어 대체 데이터 흐름을
만들어야 한다. 반대로 이 구조를2048/4096 게임 효과에 그대로 채택할 필요성도
아직 입증되지 않았다. 작은 readback의 바이트 수보다 진행을 기다리는 의존성이 문제다.

초기 사용자 baseline의 앱 전체 증분은60%에서 약4.29ms,100%에서 약8.89ms였다.
현재 모델이 이보다 효율적이라는 통합 장면 측정은 없다. max pump5–10ms 같은 최고값을
평균 CPU/GPU 비용으로 쓰지 않는다. 앞으로 같은 장면의 증분 ms와 끊김으로 비교한다.

## 5. 다음 제품 범위: 한 경로의 최소 통합 장면

**필수:** 실제 날씨/차량 입력 → SI 방울 생성·운동 → 이동 경로와 같은 시간의 deposit
→ 단순 지속 film/micro·마름·실제 경계 배수 → 기존 광학. 한 UI 시작으로 동작한다.
2048 slots로 먼저 보이며, 표시 gain과 물리는 분리한다. 보정 Smear/local impact film은 제외.

**첫 장면 통과 전 보류:** 능동 film transport, film→head pool 반환/흡수, 미세한 곡면
수송 정확도 향상, 자동 응결/열모델, 연구용 전체 누적 운동량 승인을 매 구간 필수화하는
구조, 선택 기능 추가. 병합도 기본 장면에서 드러난 결함을 해결하는 최소 구현부터 선택한다.
최종 목표에서 삭제한 것이 아니라, 비용을 정당화할 화면상 필요를 먼저 확인한다.

지속 상태의 비음수 물량과 출처·전달은 유지한다. 기본 film은 경로를 남기는 물이며,
능동 수막 유동이 빠진 근사임을 표시한다. 이를 완전한 수막 물리로 보고하지 않는다.

새 최소 경로는 기존 연구 프리뷰와 분리한 제품 실행기여야 한다. 안전한 ping-pong
소유권·순서·올바른 typed binding은 재사용하되, **기존 거부를 무조건 승인하는 방법은
사용하지 않는다.** 연구용 원장/고정 구간 감사는 재현·오프라인/선택 검증에 남기고,
제품 진행을 지배하지 않게 분리한다. 실제 CSP 명령 순서·자원 수명을 확인한 범위에서만
readback 의존성을 제거하며, 가상의 일반 GPU fence를 가정하지 않는다.

## 6. 실패 정책과 장면 평가

|상황|제품 목표 정책|
|---|---|
|방울/셀 하나의 유효하지 않은 후보|마지막 유효 상태 유지 또는 명시적인 해당 위치 재초기화; 이유·수량 기록|
|국소 계산 예산 소진|bounded 근사, 이동거리/품질 저하를 명시. 전체 FX 중단으로 확대하지 않음|
|작고 원인이 확인된 수치 잔차|해당 계산의 오차 예산으로 기록·평가. 근거 없는 전역 tolerance는 금지|
|실제 자원 오용·잘못된 형식/세대·광범위 NaN/물 복제|명확한 중단 또는 검증된 전체 초기화. 조용히 진행하지 않음|
|일시정지/백그라운드/seek/장시간 지연|모델 pause 또는 명시 reset; 무한 대기열·메모리 증가 금지|

첫 평가 단위는 새로운 독립 probe가 아니라 **이미 사용하는 실제 리플레이 장면 한 개**다.
정차→주행이 포함된 같은 시간 구간에서 화면 연결·크기·굴절·물 흐름과 전체 frame ms,
갑작스러운 정지/메모리 증가를 함께 본다. 먼저 짧은 일반 사용으로 명백한 실패를 찾고,
완성 후보 단계에서만 연속 주행 안정성을 묶어 확인한다. 매 수정마다 수분 기다리게 하지 않는다.

기본 합격 조건: 기본 방울/트레일/film이 실제 입력에 따라 함께 보이고, 가속·방향 변화와
건조에 납득 가능한 반응을 보이며, 국소 제한 때문에 전체 효과가 꺼지지 않는다.2048 장면을
성립시킨 뒤4096과 A/B한다. 원래 앱 대비 비용 증가가 있으면 그만한 화면 이익이 있는지
먼저 결정한다. 고정된 픽셀·수치 정밀도 기준을 장면을 보기 위한 사전 조건으로 만들지 않는다.

## 7. 시간·시도 상한과 재계획

다음 구현의 첫 작업 묶음은 **최소 실행 경로 추출과 실제 입력→광학 연결**이다.
추정60–120분, 신뢰도 낮음, 설계 접근1회. 이 시간은 완성/성능 달성 약속이 아니다.
작업 끝에는 실행 코드·실제 연결 여부·남은 의존성을 제시한다. 이 상한 안에 화면 연결이
불가능하면 새 probe를 만들지 말고, 차단하는 의존성을 한 번 설명한 뒤 P1/P2/P3에서
이미 사용자 관찰이 있었던 더 단순한 실행 경로로 범위를 줄인다.

첫 장면이 통과하기 전에는 추가 선택 효과 연구를 시작하지 않는다. 장면 평가 뒤 비용·
시각적 결함이 확인된 상위1–2개만 다음 작업으로 선택한다. 기존101개 prototype를
당장 정리/재작성하는 것도 제품 경로의 필수 조건으로 삼지 않는다.
