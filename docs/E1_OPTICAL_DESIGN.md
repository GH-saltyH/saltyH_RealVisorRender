# E1 재설계: 개구부 조명에 의한 내부 반사

현재 상태: 설계만 작성한다. E1 구현·UI·렌더 패스는 모두 제거된 상태다.
기존 E1 중 게임에서 동작이 확인된 기준 구현은 없다.

## 1. 이번 최소 구현의 범위

주항은 개구부를 통해 들어온 빛으로 비춰진 헬멧 내부 물체의 반사다.
부항은 같은 내부 소스가 다른 계면 경로로 맺히는 약한 고스트다.
전방 장면은 기존 투과 시야로 유지한다. 외부 카메라 HDR을 내부 반사
소스로 사용하거나 반사 방향을 반대로 바꿔 전방 화면을 조회하지 않는다.

| 항 | 소스 | 물체에서 눈으로 향하는 경로 | 역할 |
| --- | --- | --- | --- |
| 내면 반사 | 개구부 조명으로 비춰진 라이너·얼굴·내부 하우징의 출사광 | 내부 물체 → INT 반사 → 눈 | 반사상의 본체 |
| 두 번째 반사상 | 동일한 내부 소스 | 내부 물체 → INT 투과 → EXT에서 PC 내부 반사 → INT 투과 → 눈 | 두께·곡률·시선에 따른 중복상 |
| 직접 투과 시야 | 기존 전방 장면 | 외부 → EXT 투과 → INT 투과 → 눈 | 기존 시야를 유지 |

반사 소스는 눈 뒤쪽만으로 제한하지 않는다. 바이저에서 반사된 역광선이
닿는 내부 영역을 사용한다. 영상의 원인이 대부분 내부 반사라는 것은
이번 작업의 가설이며, 영상만으로 정량적인 비중을 입증한 것은 아니다.

외부로 돌아가는 외면 직접 반사와 전방 장면의 투과 고스트는 이번 범위에서
제외한다. EXT의 PC 내부 반사는 위 부항에 필요하므로 EXT 메쉬의 공간
정보는 계속 사용한다. COATING은 외부 필름 위치로 유지하며, 내면 광학
계산의 주표면은 INT다. 실제 렌더 대상은 기존 겹침 순서를 검증하여 정한다.

박막 간섭 색 이동, 스크래치/먼지 글레어, RainFX 노멀 연동은 후속 범위다.

## 2. 내부 광원 모델과 기존 하우징의 톤

계산 순서는 `외부 입사광 → 개구부/차폐 → 내부 물체 조명 → 출사광 → 바이저 반사 → 눈`이다.
개구부는 광원 측의 마스크다. 최종 반사 벡터에 정면 방향 마스크를 곱해
내부 물체의 반사를 지우는 방식으로 대체하지 않는다.

### 공유할 기존 값과 코드 위치

`realvisor.lua`의 `visorLayerDrawItem()`이 내부 조명 값을 만들고,
`rainVisorLayer.hlsl`의 `rainLayerAmbient()`와 하우징 분기가 사용한다.

| 기존 값 | E1 소스 조명에서의 의미 |
| --- | --- |
| RAIN_VISOR_LAYER_HELMET_SHADOW | 개구부를 통한 직접 태양광 차폐 사용 여부 |
| RAIN_VISOR_LAYER_SHADOW_COS_LO / HI | 개구부 방향에 대한 직접광의 부드러운 허용 구간 |
| RAIN_VISOR_LAYER_INTERIOR_AMBIENT | 내부의 환경광 감쇠 |
| RAIN_VISOR_LAYER_OPENING | 개구부에서 들어온 장면광의 내부 조명 기여 |
| RAIN_VISOR_LAYER_SUN_BOUNCE / BOUNCE_BASE | 내부 산란·간접광과 그늘의 잔여광 |
| RAIN_VISOR_LAYER_INTERIOR_SKY_CHROMA | 내부 조명의 색조 |
| RAIN_VISOR_LAYER_SHADOW_PROBE 계열 | 기존 소스 위치에서 유효한 그림자 정보 |

현재 코드의 태양 허용치는 `smoothstep(lo, hi, dot(toLight, cameraLook))`에
해당한다. 이것은 개구부 형상을 정확히 추적하는 방식이 아니라 방향 근사다.
새 E1에서는 광원 방향을 헬멧/개구부 좌표계로 평가한다. 카메라 시선과
헬멧 축을 구분하고, 현재 하우징 모델과 동일한 좌표 관계를 먼저 확인한다.

현재 내부 ambient 감쇠는 `item.interior`와 helmet-shadow 활성 조건 안에서
설정된다. 기존 조건을 포함하여 공유하며, 별도 상수로 복제하지 않는다.
현재 opening 항의 `frameLum`은 고차 MIP의 `(0.5, 0.4)` 샘플로 계산한
장면 밝기 근사이며, 개구부의 실제 평균이나 내부 반사 소스는 아니다.
새 내부 소스의 평균과는 구분한다.

직접광이 개구부 방향을 벗어나면 직접 조명 기여가 어두워져야 한다.
공유 ambient/bounce 잔여광은 같은 하우징 모델에 따라 남을 수 있다.
밤의 지역 조명은 입사 방향·광량·차폐가 확인된 경우에만 직접광으로 사용한다.

이미 그림자·개구부 조명이 적용된 내부 radiance를 캡처했다면 같은 마스크와
ambient를 다시 곱하지 않는다. 기존 화면 좌표의 shadow-probe 결과를
다른 위치의 내부 물체에 그대로 적용하지 않는다.

## 3. 내부 반사 소스의 정의

반사할 색은 내부 물체의 조명된 HDR 출사광이다. 개구부 조명은 물체의
밝기를 만드는 입력이고, 그 자체로 얼굴/라이너의 영상 정보를 만들지는 않는다.

- 내부 메쉬·재질로 출사광을 렌더하거나, 그 형상·방향을 표현하는 명시적
  내부 radiance 프록시를 만든다. 얼굴 등 없는 소스는 준비 필요 항목으로 표시한다.
- 주항과 고스트는 같은 소스를 서로 다른 광선 원점·방향으로 샘플한다.
- 내부 캡처/프록시는 충분한 방향 범위를 가져야 한다. 전방 화면만 있는
  HDR로 눈 뒤쪽 정보를 얻었다고 간주하지 않는다.
- 가까운 내부 물체의 위치에는 광선 원점·거리도 영향을 준다. 단일 위치의
  방향 맵은 근사이며 두께에 따른 시차가 정확하다고 주장하지 않는다.
- 자기 바이저·고스트·UI는 소스에 들어가지 않도록 한다.
- 엔진 큐브맵 바인딩이나 별도 캡처 API를 이미 가능하다고 가정하지 않는다.
  소스 접근과 방향 범위의 확인이 실제 광학 구현보다 먼저다.

## 4. 프레넬·두께·곡률

시작 재질은 공기/PC 계면이다. PC IOR 1.586이면 단일 무코팅 계면의
정면 F0는 `((1.586-1)/(1.586+1))² ≈ 0.05135`다. 같은 두 매질의 순서를
바꿔도 정면 값은 같다. 가장자리의 증가는 화면 가장자리 좌표가 아닌
메쉬 법선과 실제 시선각으로 계산하며, 정면 반사를 강제로 0으로 만들지 않는다.
[PC 재질 자료](https://solutions.covestro.com/en/products/makrolon/makrolon-3107_000000000057534595)

경로별 계면에서 반사·투과 계수를 계산하고 실제 INT/EXT 교차점으로
출사 원점·방향을 얻는다. 법선과 매질의 입출사를 함께 처리한다.
[PBRT 유전체 모델](https://www.pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)

정면 무흡수 평행판 근사에서 내부 소스의 주항 에너지는 `R_INT`,
두 번째 항은 `T_INT × R_EXT × T_INT`다. 동일한 무코팅 계면이면 후자가
자동으로 극히 약해지는 것은 아니다. 약한 중복상을 만드는 ghost gain은
이번 디렉션에 따른 연출값으로 별도 정의하고, 물리적 감쇠라고 설명하지 않는다.
흡수·코팅·거칠기는 이 에너지 관계를 바꿀 수 있으나 이번 최소 세트에서는
추가 효과를 이미 구현한 것으로 가정하지 않는다.

메쉬 UV는 원래 바인딩을 유지한다. 두께 2–3mm는 모델의 측정값이 아니며,
INT/EXT의 실제 간격과 단위·법선 방향을 먼저 측정한다. 일정 화면 오프셋을
고스트의 기하 경로로 사용하지 않는다.

## 5. 최소 세트의 네 가지 보조 항목

### 저주파 번짐

내부 소스를 MIP 필터링하여 부드러운 반사상을 만든다. 주항과 고스트의
필터 폭을 따로 정의할 수 있으나 둘은 같은 소스를 사용한다. 곡률은 상의
형태를 바꾸고, 표면 거칠기/광학적 번짐이 필터 폭을 정한다. 곡률만으로
반드시 흐려진다고 가정하지 않는다. [거친 유전체 반사](https://www.pbr-book.org/4ed/Reflection_Models/Rough_Dielectric_BSDF)

밝은 허용 영역이 차폐 영역으로 번지지 않도록 소스 조명·차폐를 적용한
radiance를 프리필터한다. 필터 폭은 해상도 변화에도 일관되게 정의한다.

### 가장자리 연속성

소스 범위 경계에서는 유효 영역 안쪽부터 부드럽게 fade-out한다.
반구/큐브 면 전환이나 메쉬 UV 이음새도 확인한다. UV를 테두리에 clamp하여
상 하나를 길게 늘리거나, 화면 안의 고정 오프셋으로 대체하지 않는다.

fade는 없는 방향의 정보를 복구하지 않는다. 잘못된 광선·표면 교차는
무효로 처리하고 별도 디버그로 표시한다. 매 프레임 abrupt early-return
경계가 정상 반사상의 가시 경계를 결정하지 않도록 한다.

### 상대 노출/밝기 선별

`Q = 소스 휘도 / max(내부 소스의 가중 평균 휘도, 평균 하한)`을 사용한다.
평균과 분자는 동일한 HDR 공간·노출 조건에서 측정하며, 평균은 시간적으로
완만하게 갱신한다. 밝기 선별은 soft knee로 처리한다.

정규화는 밝기 선별에만 사용한다. 최종 반사광은 실제 내부 HDR radiance와
프레넬에 비례하며, 평균 휘도로 나눠 재출력하지 않는다. 밤의 어두운 흰 물체가
상대적으로 밝다는 이유로 반사 에너지가 커지지 않도록 평균 하한을 둔다.
직접광의 존재와 차폐는 조명 모델에서 결정하며 상대 게이트로 대신하지 않는다.

### 프레넬 가중

실제 normal/view 각도와 공기/PC F0를 사용한다. 광원 선별, 상대 노출,
반사 gain, ghost gain을 독립 요소로 둔다. E1을 조절하려고 기존 하우징의
ambient/opening 값을 올려 다른 효과를 바꾸지 않도록 한다.

## 6. 디버그와 판정 기준

| 모드 | 표시 | 확인할 항목 |
| --- | --- | --- |
| 개구부 마스크 | 광원 방향의 직접광 허용치 | 헬멧 축·입사광 방향·차폐가 맞는가 |
| 내면 반사만 | 주항, 고스트 제외 | 소스가 내부 물체이며 가능한 밝기인가 |
| 고스트만 | 부항, 주항 제외 | 같은 소스의 형상이 두께·곡률에 따라 이동하는가 |
| 최종 합성 | 기존 시야 + 주항 + 고스트 | 곡면에 맺히는 형태, 경계 fade, 하우징 톤 일치 |

보조 진단에는 내부 소스/평균 휘도, 정규화 Q, Fresnel, 경로 교차 성공 여부와
유효 소스 범위를 둔다. 개구부가 태양을 막는 경우, 어두운 내부, 낮/밤,
낮은/높은 태양, 카메라 좌우 회전, 캡처 경계와 해상도 변화를 확인한다.

## 7. 이후 구현 순서와 합성 계약

1. **단색 표면:** 커스텀 셰이더가 대상 메쉬에 보이는지 게임에서 확인한다.
   소스 샘플링 없이 수행하며 표면이 보이기 전에는 다음 단계로 가지 않는다.
2. **내부 소스와 개구부:** 내부 소스가 실제로 존재하고 방향 범위를 제공하는지
   확인한다. 하우징과 동일한 조명 값을 사용한 결과를 디버그로 비교한다.
3. **주항:** 실제 법선·시선과 Fresnel로 내면 반사를 만든다. MIP 번짐,
   source-edge fade와 상대 휘도 진단을 포함한다.
4. **고스트:** 같은 소스에 INT/EXT의 별도 경로를 적용하고 연출 gain을 분리한다.
5. **합성 검증:** 네 가지 디버그 모드, 하우징 톤, INT·EXT·RainFX 표시,
   밴드 겹침과 프레임 비용을 확인한다.
6. **후속 작업:** 내면 반사가 확정된 뒤 RainFX 노멀, 필요 시 코팅 간섭과
   스크래치 글레어를 독립적으로 연결한다.

기존 post-rain HDR은 완료된 INT 광학 소스로 유지한다. 새 E1 소스로 복제하지
않는다. RainFX 노멀 연동은 연기하되 기존 RainFX 표시와 기존 렌즈의 물방울
처리를 훼손하지 않는다. 전체 렌즈/RainFX 연동은 후속 완료 조건으로 남긴다.
EXT 밴드가 최종 겹침을 덮는 순서와 공유 셰이더의 반환·깊이·알파를 유지한다.

Lua 오류 없음·컴파일 성공·API 모의 테스트 통과는 화면 출력의 증거가 아니다.
각 단계는 게임 관찰 결과로 판정한다. 이번 변경은 설계 문서에만 반영한다.
