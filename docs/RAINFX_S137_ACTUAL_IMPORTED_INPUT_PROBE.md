# s137 — actual CSP imported-input probe

Date: 2026-10-18
Status: ACTIVE

## 1. Purpose and current result

Prepare an independent default-OFF app, **RealVisor s137 imported input probe**,
to exercise the s136 read-lease provider and import bridge on actual CSP. Local
verification and the supplied fresh-session actual CSP capture pass all scoped
checks. Production remains s87 physics / s89 diagnostics, and the main app/settings
are unchanged.

The probe creates its own six-resource GPU producer for each of four cases:
real-bake YX and sparse XY, each with baseline and double End/Mean stock. It then
passes those existing whole canvases through the provider into the exact imported
26-pass candidate graph. CPU field uploads are not added to the CSP app path.
This does not connect live production rain stocks or prove zero-upload engine
internals. No queue clock, game root publication or resource retirement occurs.

## 2. Frozen recipe and producer scope

The build exports exact s136 recipes and typed values into a small standalone
template module, interning the 11 distinct consumer bodies. No parent app/module
is loaded at runtime. The package contains six files: manifest, app entry,
controller/templates and the frozen s136 provider/import bridge. Authoring
controller source is appended at build time and is not an extra installed module.

The producer reuses the frozen real-bake fixture shader. A dynamic scale changes
End/Mean mass and momentum together, including the packed bank's corresponding
rows; geometry, runs, headers, bank padding and dt stay unchanged. Producer zeros
are explicitly normalized to +0 with integer bit operations before sealing.
This reproduces the stored captured-input ABI: the first draft exposed -0 sparse
momentum whereas s136's captured controls contain +0. The original data and solver
remain unchanged; no numerical gate or output tolerance was relaxed.

Resource request keys identify the producer program, descriptors, values and
epoch. They do not claim to be a hash of unknown actual GPU contents. Captured
source values are checked separately. A private registry names the six freshly
created managed whole allocations, their revisions, sealing state and read pins.
It is not a general identity/locking service for foreign engine resources.

## 3. Prefix and lease experiment

Producer drawing is limited to two accepted calls per tick. After all six inputs
are ready, their producer write path is sealed and the provider acquires them.
The import bridge executes at most three accepted consumer passes per tick.
If compilation is pending, the exact accepted prefix is retained. The first
checkpoint is always exactly three accepted consumer passes, even if a pending
return splits that prefix across callbacks.

At the checkpoint, the probe actually calls its producer write gate and attempts
early lease return. The write must be refused without a shader call, and the
provider must refuse return because completion has not been established. These
results and cumulative read pins are included in four guard records.

All used input/output/atlas resources stay retained for the lifetime of this
one-shot probe. No provider completion call or bridge publish/retire is issued.
Shader acceptance and readback are not used as lifetime fences. Logical ordering
is the isolated experiment's assumption to test, not a production capability
upgrade. Disabling pauses work/logging; re-enabling resumes the accepted prefix.

## 4. Capture and unchanged criteria

Each case extracts all 32 resource fields to a 64×165 R32FLOAT atlas. Four cases
produce **42,240 exact float words** (including zero padding) in **228 basic-log
lines**, under the observed 1,000-call cumulative quota. Hex encoding preserves
float32 bits. State remains `logging` until all data, guards and counters have
been emitted; only then does it become `observed`.

The decoder checks:

- Exact source stock/bank/run/header controls; real basis and normal Gram model.
- All **56 selected baseline/double-stock fields** against frozen s133 controls.
  WARP and actual CSP references are kept separate. Actual mismatches remain
  visible and prevent the scoped pass.
- **48 bit-identical logical/bank field pairs**, including leaves, groups and
  end-only consumers; **16 end-only/full-gather consistency checks**.
- Per-axis and cumulative End/Mean budgets, admission, invalid recipients,
  nonnegative mass, explicit copies, padding, checkpoint guards and accepted/
  attempt counters. Curved float64 map differences remain separately reported.

This extends actual observation coverage for the specified curved recipes. It
does not establish the full legacy consumer gate, arbitrary numerical admission,
recurrent physical accuracy, the original affine criterion under new scenarios,
general completion or live adoption.

## 5. Local verification and execution

**132 WARP draws / 13 strict synthetic shader bodies** reproduce all s136 source
and output float bits after producer-zero normalization. **19 controller cases**
cover pending/resume, disable/re-enable, synchronous/duplicate readbacks, paused
logging, allocation/unknown submission/readback failures and attempt limits.
**15 decoder controls** reject malformed/incomplete/nonfinite/counter/guard data
and detect source/copy/end-only/all-zero mutations. **Nine scratch installer
checks** guard paths, hashes, unrelated files and idempotent installation.

Nominal texture payload is 337,280 bytes for the complete four-case app. This
excludes actual allocation overhead/peak memory; no FPS, timing or memory saving
is claimed. The local lifecycle backend mocks the SDK and readbacks; the WARP
adapter uploads test arrays and does not prove persistent CSP input behavior.

For the actual observation, start a **fresh game session**, open this independent
app, enable it and click **Run s137 probe once** once. Wait for `State: observed`.
Weather, driving and FPS comparisons are unnecessary. A fresh session avoids a
previously exhausted cumulative basic-log quota. Do not reload/rerun after the
quota is exhausted; the collector binds the dump to a saved fresh boundary and
the frozen installed executable package.

## 6. Actual fresh-session result

The user started a new game session and confirmed `State: observed`. The collector
accepts the newer CSP session header relative to the saved boundary and binds
the 228-line dump to the six installed executable hashes. All **42,240 float
words** and 132 once-accepted draw counters are present.

All four cases pass. All **24 source controls** (including metric bits), **56
selected baseline/double-stock controls**, **48 logical/bank pairs** and **16
end-only/full-gather checks** are bit-identical to their specified references.
Axis/cumulative budgets, admission, explicit copies, invalid recipients,
nonnegative stocks and padding also pass. The largest curved map difference
from the float64 reference remains about 4.75480e-7 cell; this is not a new
universal numerical bound.

There are 186 draw attempts for 132 accepted calls. Fourteen calls need retries,
with at most nine attempts per call; no accepted call is replayed. Each case
reports the exact three-pass checkpoint, blocked producer write and refused early
lease return. Cumulative read pins are 6/12/18/24. Thus the actual run exercises
both imported input consumption and compile-pending prefix resumption, rather
than only an immediately ready path.

This establishes the isolated managed producer/provider/import-consumer path
under these four inputs. It does not upgrade production ordering, provide a
physical completion fence, authorize repeated resource reuse, validate arbitrary
live stock admission or measure game performance. Used probe resources remain
retained, and no game roots/clock are published.

Evidence and executable package are under `docs/diagnostics/2026-10-18/s137/`.
Next bind a real interval source/header snapshot to the proven input path while
keeping producer immutability, bounded backlog and completion/refusal explicit.
The producer snapshot contract and general physical-completion ownership remain
required before runtime adoption.
