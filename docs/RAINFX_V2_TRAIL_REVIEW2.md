# RainFX v2 — trail 재검토 2 (2026-11-13)
사용자 리뷰:
- trail이 막대기처럼 길게 그어진다.
- 강한 비와 추종 장면에서 수많은 막대기가 생긴다.

도구:
- `docs/tools/rainfx2_trail_audit.py`: 지금 규칙과 물리적 끊어짐 비교.
- `docs/prototypes/rainfx2_trail_target_proto.py`: 목표 이미지 `rainfx2_trail_target.png`.

## 1. 기준 (물리 근거)
- **K1 생성:** 미끄러지는 방울의 뒤 접촉선이 따라가지 못할 때(Ca > Ca\* = θr³ / (9 ln(r/λ)), Cox–Voinov, Podgorski 2001)만 물이 남는다. → 지금 규칙(T2)을 유지한다.
- **K2 남은 선의 안정성:**
  - 선의 가장자리 각 θ_line = atan(2 h0 / hw).
  - θ_line < θr(wet): 접촉선이 후퇴(dewetting)한다. 선은 후퇴 속도 V_d = (γ/μ) θr³ / (9 ln(hw/λ))로 t_b ≈ hw / V_d 안에 구슬 줄이 된다(Rayleigh–Plateau, 간격 ~9 hw). 같은 Cox–Voinov 식이다.
  - θr(wet) ≤ θ_line: 이력 창(hysteresis) 안에서 고정된 rivulet이라 안정하다(Davis 1980). 계속 이어진 선으로 남아 증발하거나 흐른다.
- **K3 질량:** 선의 물은 구슬(또는 안정 rivulet)로 그대로 남는다. 증발하거나 뒤따르는 방울과 시트가 거둔다.
- **K4 계속 이어진 긴 줄**은 공급이 이어지는 rivulet(T7 흐름, 시트 / crown 유출)이거나 젖은 표면(K2 안정)에서만 생긴다.
- **K5 시간 규칙:** 끊어짐은 ms 단위의 꼬리 현상이다. 몇 초 뒤 보이지 않는 물에서 태어나면 안 된다(PL1의 교훈).

- **D1 (막대기의 원인):**
  - 선은 고정되어 증발(0.003 mm/s)로만 줄어든다(PL1 이후 pearling 꺼짐).
  - 그래서 보이는 시간(수 초–20 s)이 머리가 질량을 다 쓰는 시간보다 훨씬 길다 → **머리가 지나간 경로 전체(2–25 cm)가 계속 이어진 원통 렌즈로 수 초 동안 남는다.**
  - 물리적으로 그 선은 1–9 ms(프레임보다 짧음) 안에 구슬 줄이 된다.
- **D2 (수많은 막대기의 원인):** 240 km/h에서는 거의 모든 움직이는 방울(r ≥ 0.2–0.3)이 K1을 넘는다(s 3–30). 이것 자체는 물리적이다(레퍼런스: 달리는 방울 뒤의 작은 방울 줄). 문제는 모양(D1)이다.
- **D3:** 기울기 상한 때문에 θ_line은 거의 항상 24°다. 마른 면(θr 28°)에서는 모두 불안정(구슬)이고, wet > ~0.4(θr < 24°)에서는 안정(이어진 줄)이다. K2를 적용하면 막대기는 젖은 면에서만 남는다.
- D4(참고): 깊이 계수 LL 5는 문헌 Landau–Levich 1.34의 ~3.7배다. 상한에 걸리지 않는 작은 머리에서만 차이가 난다 → 머리 경로 1.0–1.4배. 선택 사항.

## 3. 제안 TR
- **TR1 (K2 / K5 상태 규칙):**
  - field / haze 패스가 F_prev와 TG_prev로 같은 판정을 한다.
  - 이번 프레임에 새로 놓인 선이 아니고 θ_line < θr(wet)이면, 그 선의 물(깊이 R, 단면 (4/3) h0 hw)은 이번 프레임에 구슬이 된다. → field R = 0.
  - 안정 선(젖은 면)은 지금처럼 남는다(증발, 흐름, 수거).
- **TR2 (구슬 = H3 미세 층):**
  - 그 물을 haze G_c에 더한다. 저장 띠 폭으로 나눈 평균 깊이 = 단면 / 2(hw + 0.9 field 텍셀).
  - 구슬 r 0.08–0.35 mm는 a_max(0.3) 아래가 대부분이라 아틀라스 조각 층과 같은 물이다(8g 원칙). a_max를 넘는 큰 머리의 줄은 G_top 초과 → hazenuc 탄생으로 셀 방울이 된다.
  - 수명주기(T1 닦기, S1 시트 흡수, 증발)가 그대로 적용된다. 탄생은 같은 / 다음 프레임에 선 자리에서 일어나므로 PL1 문제(수 초 뒤 보이지 않는 물에서 탄생)가 생기지 않는다.
- **TR3 (꼬리):** 선이 그려지는 것은 새로 놓인 프레임뿐이다 → 머리 뒤 한 프레임 이동 길이(240 km/h에서 3–13 mm)의 가는 꼬리. 물방울 + 꼬리 모양(teardrop) 연결은 유지된다.
- **TR4 (선택):** trailLL 5 → 1.34(문헌).
- 비용:
  - hzm이 셀의 field 4×4를 이미 읽으므로(P4) 'trail 물 있음' 비트를 더한다 → haze는 그 셀에서만 TG 1회 + F 1회 Load.
  - field는 판정 몇 개. 예상 +0.01–0.02 ms.

## 4. 목표 이미지 (`rainfx2_trail_target.png`, 48×32 mm, 240 km/h, 3 s)
- now: 경로 전체 막대기가 화면을 긋는다(사용자 관찰 재현).
- TR 마른 면(wet 0.3): 머리 뒤 짧은 꼬리 + 지나간 길을 따라 작은 구슬 줄(점선), 크기가 섞이고 시간이 지나며 다른 물과 합쳐진다.
- TR 젖은 면(wet 0.8): 안정 rivulet이 이어진 줄로 남는다(많은 비 / thickTrail 레퍼런스). 다만 wet는 국소값(film + trail 물, 시트 꺼짐 추종에서는 대부분 낮음)이다. 그래서 이 모습은 같은 길을 반복해서 흐르는 물길과 시트 가장자리에서만 나온다.
- 주의: 프로토타입의 렌즈와 구슬은 2D 대용이다. 게임에서는 TR2 구슬이 아틀라스 조각(R1 렌즈)으로 그려지므로 정렬은 띠 안의 무작위 조각이 된다(완전한 일직선 점렬은 아님).

## 5. 크기 다양성 검토 (사용자 질문: 물방울 크기와 맞지 않는 일관된 막대기가 해소되는가)
- **지금 막대가 크기와 무관하게 비슷해 보이는 이유:**
  1. 기울기 상한(0.45) 때문에 모든 선의 가장자리 각이 24°로 같다 → 렌즈 모양이 같다.
  2. 머리가 질량을 다 쓸 때까지 그린다 → 막대 길이 = V / 단면 ∝ r³ / r² = r. 그래서 24–57 mm로 비슷하고 머리는 사라진다.
  3. 반폭 hw ≤ 0.25 r(0.06–0.24 mm = 0.6–2.4 px)이 AA 밴드 하한(0.75 px)에 눌려 1–3 px 선으로 수렴한다.
- **TR1 + TR3:** 이어진 선을 프레임 한 칸으로 줄인다 → 긴 막대의 원인(1–3이 몇 초 동안 쌓이는 것)은 사라진다.
- **TR2(아틀라스 편입)는 크기 다양성을 지키지 못한다.**
  - 줄의 물을 저장 띠(2 hw + 1.06 mm)에 펴면 깊이가 0.25–3 G_sat이다. 조각 크기는 도착 반경(0.145 mm)으로 고정되고, 덮임은 0.02 / 0.06 / 0.22다(머리 r 0.3 / 0.5 / 1.0).
  - → 작은 머리의 줄은 거의 사라지고, 남는 조각은 모두 같은 크기다. 목표 그림의 '머리 크기에 비례하는 구슬 줄'이 되지 않는다.
- **TR2b (대안, 권장): visor가 줄을 구슬 줄로 그린다.**
  - TG(점, 방향, hw)와 field R(깊이 = 물 양)를 그대로 쓴다.
  - 구슬 반경 r_b = (9 hw · (4/3) h0 hw / K)^(1/3) ≈ 0.3 r(0.085 / 0.16 / 0.34 mm), 간격 9 hw ≈ 2.2 r(0.55 / 1.04 / 2.18 mm).
  - 줄 방향 위상(dot(p, τ) / λ)과 해시 지터: 간격 ±30 %, 크기 0.75–1.2배, 옆으로 ±0.3 hw.
  - 머리 크기 분포가 그대로 줄의 굵기와 간격 분포가 된다.
  - 구슬은 셀 방울과 같은 렌즈 커널(r2Kernel)로 그린다. 수명은 field R(증발, 뒤따르는 방울 수거, S1 시트, T1 닦기와 같은 경로)을 따른다.
  - 비용: 기존 rivulet 커널 대신 가장 가까운 구슬 2–3개 → visor +0.01–0.03 ms 예상.
  - 한계:
    - 그린 구슬은 움직이지 않는다. 240 km/h에서 r_b 0.1–0.2 mm 방울의 실제 속도는 ~0.05–0.09 m/s다.
    - 점렬이 너무 오래 쌓이는지 프로토타입 / 게임에서 확인이 필요하다(증발 0.003 mm/s → 구슬 r 0.16은 수 초).
- **젖은 면의 안정 rivulet(K2):** 이어진 선으로 남는다. 상한 각 24° 때문에 모양이 같아지는 문제는 남는다 → 단면을 θr–θa 사이 각으로 두는 변경은 TR 이후 판단.

## 6. 끊긴 막대 반복 (사용자 이미지, 2026-11-13)
- 관찰: 하나의 긴 경로 안에 짧고 밝은 막대가 간격을 두고 여러 번 반복된다(점선 막대).
- **원인:**
  - trail 패스(trail.hlsl)와 field 패스(r2TrailCand)는 텍셀 셀 ±2 셀 안에 **프레임 끝 위치**가 있는 방울만 본다.
  - substep 이동이 프레임당 M = substeps × 1.95 셀까지 커지면, 각 프레임 경로 중 끝에서 ~2.5 셀(≈ 3 mm)만 선이 저장되고 앞쪽 (M − 2.5) 셀은 비어 있다.
  - → 3 mm 막대 + (M − 2.5) × 1.18 mm 간격(M 3.9 / 4.9 / 7.8에서 1.7 / 2.8 / 6.3 mm)이 프레임마다 반복된다. haze의 T1 결함(H3 spec 8k B)과 같은 원인이다.
  - 막대가 수 초 동안 남기 때문에(D1) 점선 전체가 오래 보인다.
- **새 대안과의 관계:**
  - TR1 / TR3(선은 새 프레임 꼬리만, 나머지는 구슬)은 '오래 남는 막대'를 없앤다.
  - 그러나 저장이 끊긴 구간에는 구슬 물도 없다 → 구슬 줄도 같은 간격으로 끊긴 무리가 된다. **이 창 문제를 따로 고쳐야 한다.**
- **TR0 (substep trail 기록, T1과 같은 방식):**
  - trail 후보 수집(r2TrailCand)을 cells substep마다 그 substep의 S_next로 돌린다. substep 끝마다 경로 모든 점이 ±2 셀 안에 있으므로 빈 구간이 없다.
  - 저장: TG(선 기하)와 trail 물(R, F4 이후 h). 같은 텍셀에 여러 substep의 선이 겹치면 지금 규칙(깊은 / 새 선이 대체).
  - 구현:
    - (a) trail 패스를 substep마다 실행(field 해상도, 25 후보, wm의 선분-사각형 컷 재사용). 예상 0.03–0.05 ms × substeps.
    - (b) trail 물 장부를 field 패스에서 trail 패스로 옮겨 field는 프레임 1회 유지.
  - CSP의 다중 렌더 타깃이 확인되면 wm에 합칠 수 있다(현재 미확인).
- 머리 질량 손실(cells r2Predict)은 substep마다 이미 경로 전체로 계산된다 → TR0 뒤에는 장부와 그림이 일치한다(지금은 손실된 물의 일부만 저장).
