# E1 1단계: 커스텀 표면 출력 테스트

반사 구현에 앞선 렌더 경로 진단이다. 새 반사 소스나 고스트는 아직 없으며,
2026-10-08 사용자 게임 평가로 기본 출력 경로 검증을 통과했다.

## 조작 위치

KN5 탭 → GLASS_COATING_OVERLAY 머티리얼 팝업 →
`E1 surface output test`를 활성화한다. 기본값은 꺼짐이다.

| 설정 | 의미 |
| --- | --- |
| Target 0 | COATING, 녹색 |
| Target 1 | INT, 청록색 |
| Target 2 | EXT, 자홍색 |
| Placement 0 | 해당 메쉬의 기존 커스텀 머티리얼을 그린 직후. 후속 패스가 덮을 수 있음 |
| Placement 1 | 바이저 스택 마지막, 깊이 ReadOnly. 기본값 |
| Placement 2 | 스택 마지막, 깊이 Off. 깊이 차폐 분리용 |
| Opacity | 실제 프리멀티플라이 알파, 기본 0.5. 필요하면 1로 평가 |

원본 메쉬와 original transform으로 직접 render.mesh를 호출한다. 텍스처,
HDR, 프레넬, UV 조정, 네이티브 머티리얼 교체, 추가 KN5 인스턴스를 사용하지 않는다.
깊이는 쓰지 않는다. 호출 후 임시 메쉬 표시와 깊이 상태를 복원한다.

Placement 1/2는 시인성 진단을 위해 밴드 위에도 색을 그린다. 밴드가
색칠되는 것은 이 테스트의 예상 출력이며 최종 E1의 합성 정책은 아니다.
Placement 2는 하우징/차폐된 영역에도 색이 보일 수 있다. 정상 차폐 판정에는
Placement 1을 사용한다. 테스트를 끄면 기존 경로로 돌아간다.

## 평가 목록

1. **호출 도달:** 활성화한 뒤 Draw attempts가 증가하는가? 증가하지 않으면
   팝업의 Blocked/Waiting 문구를 기록한다. 검사 대상의 Visible도 확인한다.
2. **기본 출력:** Target 0, Placement 1, Opacity 0.5에서 녹색 곡면이 보이는가?
   부족하면 Opacity 1에서 다시 확인한다. API 결과 true만으로 성공 판정하지 않는다.
3. **깊이 차폐:** Target 0을 유지하고 Placement 2로 바꾼다. 1에서는 없고
   2에서만 보이면 깊이/차폐 경로를 조사한다. 둘 다 없으면 결과와 호출 횟수를 기록한다.
4. **메쉬별 출력:** Placement 2에서 Target 1/2를 각각 확인한다. COATING만
   안 보이는지, INT/EXT도 안 보이는지 구분한다. 원래 메쉬 위치/형상을 따르는지 확인한다.
5. **덮어쓰기:** Target 0에서 Placement 0과 1을 비교한다. 1은 보이고 0은
   안 보이면 후속 RainFX/INT/EXT 패스의 덮어쓰기를 조사한다.
6. **카메라 추종:** 시선을 좌우·위아래로 움직여 단색이 화면에 고정되지 않고
   실제 바이저 메쉬의 실루엣과 움직임을 따르는지 확인한다.
7. **표시 연동:** 선택 대상의 Visible을 끄면 단색도 없어지고 팝업에 차단
   이유가 표시되는지 확인한다. 다른 메쉬의 Visible을 끈 결과와 혼동하지 않는다.
8. **복원:** 테스트를 끈 뒤 RainFX 물방울, INT 굴절/블러, EXT 밴드·경계 노멀이
   테스트 전과 같은지 확인한다. 날씨나 튜닝값은 비교 중 동일하게 유지한다.

## 필요한 결과 기록

`Target / Placement / Opacity / Draw attempts / API result / 보임·안 보임`
조합과 화면 캡처를 기록한다. 우선 필요한 조합은 0/1, 0/2, 1/2, 2/2,
0/0이다. 최초 렌더 경로 검증에는 FPS 측정이나 광학 밝기 평가는 필요하지 않다.

게임에서 최소 하나의 메쉬에 단색 출력이 확인되면 그 근거로 다음 단계를
진행한다. 현재 내부 소스용 API 후보는 GeometryShot의 custom pass이며,
월드 법선/헬멧 축 접근 API는 로컬 SDK에서 확인했지만 내부 radiance 캡처는
아직 구현·검증하지 않았다. 렌더 진단이 성공했다는 이유로 소스 접근까지
성공했다고 판정하지 않는다.

## 2026-10-08 게임 평가 결과

- Target 0 / Placement 1: 녹색 표면 표시 및 Draw attempts 증가 확인.
- Depth Off: 하우징을 덮어 표시됨. 정상 광학 합성에는 ReadOnly 사용.
- Target 1: INT 청록색, Target 2: EXT 자홍색 표시 확인.
- Placement 0과 1 모두 표시됨. 작은 차이는 후속 패스 합성에서 생길 수 있으며,
  이 결과만으로 UV나 반사 위치가 맞다고 판정하지 않는다.
- OFF: 기존 바이저 형태 복원 확인.

기본 렌더 경로 검증을 통과하여 2단계 내부 소스 미리보기로 진행한다.
이전 E1 구현의 성공 근거로 소급하지 않는다.
