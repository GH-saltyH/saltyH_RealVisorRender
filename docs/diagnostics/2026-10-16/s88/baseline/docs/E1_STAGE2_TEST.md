# E1 2단계: 내부 소스 미리보기

1단계 단색 출력은 사용자 게임 평가를 통과했다. 이번 단계는 실제로 보이는
내부 소스와 조명 평가이며 아직 반사상·고스트를 유리에 합성하지 않는다.

## 조작

KN5 → GLASS_COATING_OVERLAY 머티리얼 팝업에서 1단계 테스트를 끄고
`E1 internal source preview`를 켠다. 기본값은 OFF.

- Mode 0: 내부 재질 HDR 소스. 표시용만 C/(1+C)로 압축한다.
- Mode 1: 캡처에 그려진 표면 위에 기존 개구부 방향 가중치를 회색으로 표시한다.
  이것은 공간별 광선 차폐 마스크가 아니다.
- Origin offset: 눈 위치에서 헬멧 모델의 +Z 방향으로 이동한 캡처 원점.
  기본 0.025 m는 진단용 초기값이며 실제 INT 표면에서 보정된 위치는 아니다.
- FOV: 뒤를 바라보는 캡처의 시야각, 기본 120도.

## 소스의 범위와 한계

GeometryShot의 사용자 opaque 콜백에서 FRAME, RUBBER, FABRIC 하우징만
그린다. 각 항목의 기존 Visible 설정을 존중한다. 월드·차체·UI·유리·물방울은
이 소스에 그리지 않는다. 얼굴 메쉬가 없으므로 얼굴 반사는 아직 재현하지 않는다.
메쉬의 실제 월드 변환을 유지하며 별도의 재질 파라미터 인스턴스를 사용한다.

기존 하우징 조명 모델을 재사용한다. 내부 항목(RUBBER/FABRIC)의 태양항은
HELMET_SHADOW/개구부 방향값을 사용하고 FRAME은 기존 FRAME 조명 규칙을 유지한다.
Mode 1은 내부 항목에 쓰이는 방향값이다. 실제 공간별 그림자나 지역 광원의
가시성을 측정하는 기능은 아직 아니다. 기존 방향 계산의 기준도 cameraLook이다.

메인 HDR의 낮은 주파수 밝기는 하우징 ambient 추정에만 쓰며 상 자체를 복사하지
않는다. 이는 실제 내부 평균 휘도와 구분해야 한다. 메인 카메라용 화면 그림자
프로브는 다른 캡처 시점에 재사용할 수 없어 OFF. 이 단계에서 기존 하우징과
그림자가 완전히 일치한다고 기대하면 안 된다.

## 게임 평가 목록

1. **캡처 도달:** Updates / housing callbacks가 증가하고 오류가 없는지 확인.
2. **내용:** Mode 0에서 라이너/테두리 표면이 보이는지 확인. 트랙·하늘·차체·
   UI·밴드가 그대로 찍히면 소스 범위 오류다. 검정뿐이면 캡처도 함께 전달.
3. **원점:** 기본값에서 보이지 않으면 offset 0, 0.05, 0.10 m와 FOV 150을
   순서대로 평가. 어느 조합에서 내부 표면이 나타나는지 기록한다.
4. **조명 방향:** Mode 1에서 태양이 개구부 방향일 때 밝고 반대쪽일 때 어두운지
   확인. Mode 0의 내부 재질 밝기도 비교한다. FRAME은 동일 게이트 적용 대상이 아니다.
5. **HDR 에너지:** 같은 설정으로 밝은 낮/그늘/밤에서 Mode 0 비교.
   밤의 흰 재질이 낮처럼 강하면 내부 조명 추정을 다음 단계 전에 수정한다.
6. **카메라 이동:** 좌우·상하 이동에서 표면과 캡처 변화가 연속적인지 확인.
   영상 경계 밖은 아직 소스 커버리지 누락이며 늘려 채우지 않는다.
7. **격리/복원:** 켰을 때 주 화면의 하우징·INT 블러·EXT 밴드·물방울이
   바뀌거나 사라지지 않는지, OFF 뒤 원래대로 유지되는지 확인.

필수 결과는 Mode 0/1 캡처, offset/FOV, Updates/callbacks, 오류문구다.
내부 소스가 게임에서 확인된 뒤 주반사 좌표·프레넬·블러·경계 fade·상대 휘도
선별을 연결한다. 성공 API 응답만으로 내부 소스의 시각적 정확성을 판정하지 않는다.

## 로컬 검증 결과

- 전체 realvisor.lua LuaJIT 문법 컴파일 통과.
- 미리보기 인라인 셰이더 FXC ps_5_0 /Ges /WX 컴파일 통과.
- 캡처 성공/그리기 실패/재시도/OFF 자원 해제와 각 메쉬의 이전 Visible
  상태 복원 mock 검사 통과.
- 메인 카메라 그림자 프로브 및 1단계 표면 테스트의 캡처 유입 차단 확인.
- git diff --check 통과. 실제 소스 표면과 조명은 게임 평가 대기.

## 사용자 게임 평가: 소스 격리 통과

Mode 0에서 카메라 시야 밖 내부 모델(라이너/패브릭/프레임)만 관찰되며
나머지는 검정이다. 기존 오버레이에 영향이 없었다. Mode 1은 개구부를
태양/하늘 방향으로 향할수록 실루엣이 밝아지고 반대 방향에서는 어두워졌다.
이는 기존 방향 가중치의 동작 확인이며 실제 내부 조도나 지역 광원 검증은 아니다.
밤에는 일부 방향에서 밝아졌으나 태양/달/지역조명 중 원인은 확정할 수 없다.

이후 UI에 Opening weight와 directional HDR luminance를 분리 표시한다.
E1 source directional light weight는 E1 소스의 태양/방향광과 bounce 항만
조절하며 기존 주 화면 하우징 조명값은 바꾸지 않는다. 지역 조명 수집은 아직 없다.
