# 하우징 KN5 원본 네이티브 경로 (2026-10-09)

## 현재 선택

- `BODY_FRAME`, `BODY_GLASSLINE`, `BODY_FABRIC`를 메인 카메라와 E1 내부 반사 소스에 사용한다.
- KN5에 구운 셰이더·텍스처·재질 값·블렌드·깊이·컬링 상태를 유지한다. 자동 셰이더 교체나 공통 회색 텍스처 주입을 하지 않는다. 기존 개별 재질 편집기는 명시적인 사용자 조절용으로 유지한다.
- `BODY_FRAME_OVERLAY`, `BODY_GLASSLINE_OVERLAY`, `BODY_FABRIC_OVERLAY`는 원본 파일에서 삭제하지 않는다. 프로필의 Visible 설정과 관계없이 숨기고 그림자 및 하우징/반사 계산에서 제외한다.
- 새 메쉬가 없으면 누락된 이름을 표시한다. 이전 overlay 메쉬로 대체하지 않는다.
- `DRIVER_FACE`, `DRIVER_BALAKLAVA`는 선택적으로 E1 색상/깊이 소스에 포함하고 메인 카메라에서는 숨긴다. KN5 원본 재질을 유지한다.

## 캡처 범위

엔진 변환 갱신을 위해 캡처용 KN5 루트는 등록된 상태로 유지한다. GeometryShot 입력에는 모델 전체 루트 대신 위의 세 하우징과 선택적 얼굴 메쉬의 참조 합집합만 넘긴다. 유리, coating, MIRROR, 이전 overlay 및 다른 메쉬는 입력에 포함하지 않는다. 캡처 복제본은 메인 출력과 장면 그림자에 참여하지 않는다. INT / EXT / COATING의 서로 다른 UV는 공유하거나 복사하지 않는다.

메인 하우징용 HDR 캡처 → custom scene output, 추가 외피 그림자 복제본, 가상 shadow probe 및 이전 BVH 검증 경로는 사용하지 않는다. 기존 BVH DDS는 이전 모델에 대해 생성된 자료이므로 새 메쉬에 재사용하지 않는다. 베이커의 이름만 새 이름으로 갱신했으며 런타임 재활성화 전 모델과 데이터의 재검증이 필요하다.

## E1 사용 시 검정 폴리곤 대응

캡처용 복제 메쉬가 참조 구성 시 Visible로 켜지고 뒤늦게 root opaque 패스에서 숨겨지는 수명 문제를 수정했다. 복제본은 프레임 준비와 캡처 참조 구성 동안 숨기고, 동기 GeometryShot 갱신 동안에만 선택된 메쉬를 켠다. 성공·pending·오류 모두 즉시 메쉬와 루트를 숨긴다. 메인 렌더 콜백은 추가 방어로 유지한다. 메인 카메라의 원본 하우징 재질/가시성은 이 처리의 대상이 아니다. 실제 검정 폴리곤 제거 여부는 게임 검증이 필요하다.

후속 테스트에서 검정 폴리곤은 사라졌지만 lit/aperture 소스가 검게 나왔다. 네이티브 GeometryShot 갱신 중 발생할 수 있는 장면 렌더 콜백에서 숨김 처리가 캡처 자체를 지우지 않도록 `nativeCaptureActive` 보호를 추가했다. 갱신 성공/실패/pending 이후 보호를 해제하고 즉시 숨김 처리를 적용한다. 모의 검증에서 캡처 도중 숨김 콜백을 호출해도 선택 메쉬가 유지되는지 확인했다. 얼굴과 발라클라바의 checker 진단은 metric depth와 동일하게 양면으로 그리며, KN5 네이티브 재질의 컬링 설정을 수정하지 않는다. lit 복구와 얼굴 checker 표시는 게임 재검증이 필요하다.

그다음 게임 테스트에서 최초 lit/aperture 캡처와 얼굴 checker는 확인됐지만 이동 뒤 소스가 검게 변했다. 현재는 위의 “프레임 준비 동안 숨김” 방식을 변경했다. `script.update` 끝에서 카메라 추적·offset·motion·calibration이 완료된 최신 하우징 포즈를 복제 루트에 복사하고, 허용된 복제 메쉬만 켜서 엔진 프레임 변환 갱신에 참여시킨다. `onSceneReady` 캡처 종료 시에는 모든 복제 메쉬와 루트를 즉시 숨긴다. 다음 프레임 시작/조기 반환에서도 이전 복제본을 숨겨 둔다. checker 모드에서는 네이티브 복제본 준비를 하지 않는다. 이는 캡처 직전에만 켜서 네이티브 월드 변환이 최초 위치에 남는 것을 방지하기 위한 변경이다. 이동을 모의한 여러 프레임의 변환 준비와 캡처 후 숨김을 검증했으며, 실제 이동 후 lit/aperture 유지 여부는 게임 확인이 필요하다.

## 추후 연구 과제

ksPerPixelMultiMap와 같은 질감/라이팅을 내는 전체 커스텀 파이프라인은 보류한다. 범위는 diffuse/normal/maps/detail/AO 및 Fresnel 재현, 엔진 HDR 광원·그림자·환경반사 자원 접근, BODY_FRAME_MIRROR 기반 개구부 차폐, 렌더 순서/깊이/모션 벡터/DLSS 연동과 움직임 중 음영 안정성, 비용 측정이다. 기존 custom scene output 실험은 비교 자료로 코드와 이력에 보존한다.

이번 선택은 네이티브 렌더의 일렁임과 역광 한계를 수용한다. 새로운 차폐나 DLSS 안정화가 구현됐다는 뜻은 아니다. 캡처 범위와 원본 재질 보존은 로컬 모의 검증 대상으로, 실제 화면·반사상은 새 KN5로 게임에서 확인해야 한다.
