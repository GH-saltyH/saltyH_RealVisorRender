# 트레일 표시 이력과 수막 표현 몫 분리

후속: [실제 제품 source export](RAINFX_ACCEPTED_TRAIL_SOURCE_EXPORT.md)가 GPU16슬롯에
선분과 trail-only coarse 기여를 보존하도록 연결되었다. 아래 Python 검증의 범위는
그대로이며, 실제 fine optics 소비는 아직 미연결이다.

2026-10-25. 유한 이력 모듈과 셀별 표시 물량 분리 함수를 구현했고, 실제 기록 선분의
Python 장면에 연결했다. **게임의 `rain_product_visual`에는 아직 호출을 추가하지 않았다.**
GPU 원천 데이터/accepted receipt 연결이 남아 있으며 새 물리 수막을 만드는 기능이 아니다.

## 구현

- `rain_trail_history.lua`: 기본16개 step 묶음, 최대32개. 묶음당4096개 이벤트까지만
  허용하고 payload는 소유자가 유지하는 불변 핸들이다. 모듈 자체는 GPU 생성/읽기가 없다.
- 기본 표시 수명.5초, 마지막.15초 smooth fade. 이는 **표시 세부 정보의 수명**이며
  물의 증발 시간이나 물리 트레일의 수명 설정이 아니다. 실제 재질에 맞춘 확정값도 아니다.
- accepted 입력의 시뮬레이션 시간만 사용한다. 입력이 없으면 벽시계로 늙지 않는다.
  배경/일시정지에서 임의로 물리 시간을 진행하지 않는다.
- 중복/오래된 입력은 무시한다. serial 누락이나 epoch/geometry 변경은 세부 이력을
  비우며, 모르는 구간을 선으로 연결하지 않는다. 물리 solver를 fault로 만들지 않는다.
- 저장 한도를 넘기면 오래된 세부 표시만 해제한다. 수막 재고를 삭제하거나 유출로
  기록하지 않는다. 거친 수막 표현이 계속 해당 물을 맡는다.

게임에서 실제 불변 GPU 핸들의 수명을 보장하는 구현은 별도로 필요하다. 문자열
epoch와 accepted flag만으로 GPU fence/소유권이 증명되는 것은 아니다. 이 모듈의
0 GPU 자원 수치를 전체 detail 파이프라인의0 추가 메모리로 해석하지 않는다.

## 이중 표현 방지

현재 셀의 실제 수막 물량을F, 살아 있는 표시 이력의 fade 가중 coarse 기여를R이라 하면:

```text
세부 표시 예산 C = min(max(R,0), F)
거친 수막 나머지 B = F-C
같은 셀 안의 세부 형상 가중치 w_j를 정규화:
세부 픽셀 물량 D_j = C*w_j/sum(w)
sum(w)=0이면 C를 균일 분배
최종 표시 물량 = B + sum(D_j) = F
```

계산은 각 기존1024×256 셀 안에서만 수행한다. 서로 다른 셀로 물을 이동하지 않는다.
따라서 다른 공급으로 들어온 수막은 나머지에 남고, 재고가 줄면 세부 표시 예산이
재고를 넘지 않는다. micro 채널은 별도이며 이 예산에 더하지 않는다.

이는 **표시 예산 규칙**이다. 증발 후 어느 분자가 어떤 공급에서 왔는지 추적하는
물리적 구성비 모델은 아니다. 최근 기여를 재고 이하로 자르는 것만으로 실제
trail 잔존량의 출처를 확정할 수 없다. 짧은 표시 이력에서 사용하는 근사다.

## 화면 품질과 비용 판단

수명이 끝나면 세부 굴절은 약해지고 기존 coarse 수막으로 돌아간다. 이것은 물이
증발하거나 배수된 장면이 아니다. 단지 이력과 표현을 교체한 결과다.
셀별 정규화와 coarse/detail 전환에는 격자 흔적이 남을 수 있다. 이 장면은
연속32Hz 보간, 최종 reference C/B/A 품질 또는 재질 튜닝 통과로 취급하지 않는다.

1초의16묶음 조건에서 세부 형상을 해상도 안에서 확보하지 못해 균일 분배한 물은
.017984mm³, 세부 예산의 약14.3%였다. 가는 형상으로 coarse support 전체를
복원할 수 없다는 제약이 남는다. 없는 중심선을 만들어 이 비율을 숨기지 않는다.

Lua 이력 관리 비용은 최대32묶음을 순회하는 수준이다. 하지만 실제 GPU 표현
비용은 아직 평가되지 않았다. 예를 들어 묶음마다1024×256 R32F를 보관하면
16묶음에16MiB이며,4096방울×16묶음×3 float4 기하는3MiB다. 여기에 고해상도
출력/비닝/필터 자원이 더 필요할 수 있다. Python의 전체 fine atlas를 그대로 게임에
할당하거나 모든 픽셀에서 모든 이력을 순회하는 구현을 채택하지 않는다.

## 다음 제품 연결의 구체적인 범위

현재 제품은 accepted bank의 state/meta/film/micro/receipt만 optical snapshot에
공급한다. 최근 trail의 선분과 정확한 coarse 기여는 보존하지 않는다. 따라서 이번
모듈을 실제로 호출하려면 producer의 전달 선분과 기존 source raster에서 **trail만의
기여**를 같은 accepted 구간에 묶어 내보내야 한다. 합쳐진 수막 총량의 차분을
trail로 간주하면 직접 공급·증발·micro 합류가 섞이므로 사용하지 않는다.

다음은 이 데이터 연결 한 가지에 한정한다. 별도 probe나 물리 정밀도 연구를
선행하지 않는다. 기존 게임 효과는 이번 단계에서 달라지지 않는다.
