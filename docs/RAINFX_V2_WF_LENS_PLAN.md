# RainFX v2 — Water Field 물방울 렌즈 이식 계획 (분석·예비 비용, 2026-10-26)

요청(사용자, rev17 리뷰): 기본 버전(P0 아님)의 Water Field(WF) 물방울이 여러 장면·각도·톤에서 더 잘 융합된다.
v2 물방울은 rim bevel을 1.5 mm 아래로 내리면 중앙이 흐릿한 반무광 알루미늄 판처럼, 장면에 따라 기름때처럼 보인다.
WF의 외형 결정 요인과 `settings_mats.ini` 튜닝을 해석하고, v2에 이식하는 안과 비용·표현 예비 분석을 만든다.

근거 자료: `shaders/rainVisorDynamicDrop.hlsl`(WF 분기 `rainDropMain` 708–1030행, `rainWaterLensColor`),
`realvisor.lua` cfg(707–860행, `waterKernel` 10002행), `settings_mats.ini`, `docs/RAINFX_WATER_FIELD.md`.
오프라인 비교: `docs/prototypes/rainfx2_wf_lens_compare.py` → `docs/rainfx2_wf_vs_v2_lens.jpg`, `_zoom.jpg`.

## 1. WF 물방울이 외형을 결정하는 방식

|단계|WF 구현|결정 값(유효값 = cfg 기본, settings_mats 덮어쓰기 없음 표시)|
|---|---|---|
|높이 커널|64² 텍스처 `h = 1 − r²`(직선 알파)를 반지름 × `KERNEL_SCALE` 쿼드로 2048² fp16 캔버스에 스탬프|`KERNEL_SCALE` 1.24|
|합성|알파 블렌딩 = **메타볼 합집합** `a + b − ab`. 겹친 방울은 다리를 놓고, 로브·퍼들·꼬리·움직임 늘임이 같은 캔버스에서 합쳐진다|`SHAPE_STRENGTH` 0.85, 로브 on, 퍼들 25 %(≥ 1.4 mm), `MOTION_STRETCH` 0.35, 꼬리 1.5 R|
|실루엣|합집합 높이 G에 임계, AA 폭 = max(0.75·fwidth(G), 0.004) (+ 큰 방울 0.10)|`THRESHOLD` 0.35 → 1 − (r/1.24R)² = 0.35 ⇒ r = 0.997 R|
|기울기|G의 유한 차분(물리 간격 0.252 D) × 반지름 px = **무차원 기울기, 가장자리 ≈ 1.3, 중심 0, 반경에 선형**|`NEW_TRAIL_HEAD_GRADIENT_D` 0.252(settings_mats)|
|굴절|`uv + slope × 0.69 × (H/W, 1)` — 중심을 지나쳐 샘플 → **반전·축소 상**, 이웃 방울끼리 일관|`REFRACTION` 0.69(화면 높이/기울기 1)|
|블러|mip = 3 + 1.5·|s|/1.5 (+ 큰 방울 1.5·largeW, 시트 블러)|`SCENE_MIP` 3, `SLOPE_MIP` 1.5, `LARGE_*` 8–30 px|
|큰 방울|drop 크기 셀의 값 노이즈로 내부 상 4 px 왜곡, 부드러운 경계|`LARGE_WARP_PIXELS` 4, `WARP_CELLS` 0.6|
|하늘 보정|굴절 샘플이 하늘(깊이 > 0.99999)이면 WeatherFX 안개색 × 제한된 대비(0.95–1.12)로 대체|`BIRTH_MASK_SKY_CORRECTION` on|
|림|에너지 손실 0.75 × smoothstep(0.7, 1.3, |s|) → **어두운 테두리**; 아래쪽 림(화면 위를 향한 기울기)에 안개색 글린트 0.45·facing⁴|`EDGE_LOSS` 0.75, `LOSS_START/END` 0.7/1.3, `GLINT` 0.45|
|톤 제한|**꺼짐**(`WATER_TONE_ENABLED` false). 굴절 상의 명암을 그대로 둔다|—|
|불투명도|1.0(시트만 0.35)|`OPACITY` 1|

핵심: WF 물방울은 **방울 전체가 하나의 연속 렌즈**(포물면, 기울기가 중심 0 → 가장자리 1.3로 선형)이고, 강한 굴절(0.69)로
뒤집힌 주변 풍경을 담는다. 어두운 테두리와 아래쪽 하이라이트가 어떤 배경에서도 "물방울"이라는 윤곽을 만든다. 상은 mip 3으로 고르게 흐리다.

## 2. v2(rev17)가 다르게 보이는 이유 (같은 방울·배경 오프라인 비교)

|요인|v2 rev17|결과|
|---|---|---|
|윗면 형상|평평한 윗면 + 고정 폭 림(CSP 맵 모방) + 약한 돔 0.25. bevel < R이면 중앙 기울기 ≈ 0.25·q|중앙이 배경을 거의 그대로 통과 → **평평한 판**(bevel 0.32 = 회색 알루미늄)|
|굴절 크기|물리값 (n − 1)·FovK ≈ 0.29 화면 높이|WF의 0.42배. 반구형 방울(접촉각 ~90°)은 실제로 볼 렌즈에 가까워 강하게 반전·축소한다 → 0.69가 체감상 맞다|
|톤|톤 창 하한 0.85(rev16) + `dropVeil` 0.2|방울 색이 배경 평균으로 끌려가 **무광 회색/분홍**|
|림|edgeLoss 0.2(rev16에서 낮춤)|윤곽이 약해 장면과 분리되지 않고 번짐(기름 얼룩)|
|윤곽|사인 3배음 반지름 노이즈 0.25|부드러운 혹 모양 → 기름 방울 느낌|
|겹침|셀마다 최고 높이 승자|닿은 방울 사이에 이음매(합집합이 아님)|
|블러|aperture 0: mip 0.5(선명한 인쇄 상), aperture > 0: 광선 분산으로 mip 최대 8(뭉개짐)|중간이 없음|

오프라인 비교(`rainfx2_wf_vs_v2_lens.jpg`): bevel 0.32는 회색 판, bevel 1.5는 반투명 분홍 거품, WF 규칙은 반전 상·어두운 테두리·아래 하이라이트를 가진 물방울.

## 3. 이식 안 (rev18 제안) — 시뮬레이션은 v2, 렌즈는 WF

v2의 셀 상태(위치·부피·시드·이동), 물리, 합체, 수막·haze·흔적은 그대로 둔다. `visor.hlsl`의 방울 평가만 WF 규칙으로 바꾼다.
캔버스 스탬프(CPU 쿼드, 2048² fp16) 없이 **5×5 후보에서 해석적으로** 계산한다.

1. **높이 합집합:** 후보마다 `h = 1 − (d / 1.24 R)²`. 시드로 0–2개 로브 커널(방향 = 시드 해시, 거리 0.55 R, 크기 0.45–0.55 R; R > 0.5 mm만).
   점화식 `G ← G(1 − h) + ∇h·P`, `P ← P(1 − h)` → U = 1 − P, ∇U = G. 반지름은 h 가중 평균.
   움직이는 방울은 이동 방향으로 `MOTION_STRETCH` 0.35만큼 타원(이동 패킹이 이미 상태에 있음).
2. **실루엣:** smoothstep(0.35 ± max(0.75·fwidth(U), 0.004) + 0.10·largeW + 디포커스 폭).
3. **기울기·굴절:** s = ∇U × R_px(가장자리 ≈ 1.3). 오프셋 = s × 0.69 × (H/W, 1). mip = 3 + 1.5·|s|/1.5 + 1.5·largeW (+ 큰 방울 왜곡 4 px).
4. **색:** 하늘 보정·톤 패스 **없음**(§6), 림 손실 0.75(0.7–1.3), 글린트 0.45·facing⁴, **톤 창 끔**, `dropVeil` 0.
5. **디포커스(aperture):** 광선 평균 대신 WF식으로 근사 — 실루엣 폭 += rb / R, mip += log2(1 + rb·px/mm). aperture 0이면 순수 WF.
6. **수막과의 결합:** 기존대로 수막 굴절 오프셋을 더하고, 두꺼운 수막에서 방울 윤곽을 흡수(`filmAbsorb`). 산란 베일은 rev17(표면 전용) 유지.
7. **물리 크기 일치:** 셀 상태의 r(부피 → 구면 캡)과 WF 커널 R을 같게 쓴다(임계 0.35 ⇒ 실루엣 = R).
8. UI: `Drop lens: WF (default) / CSP bevel (rev4)` 전환, WF 값(굴절 0.69, scene mip 3, slope mip 1.5, edge loss 0.75, glint 0.45, lobes) 슬라이더.
   CSP bevel 경로는 비교용으로 1–2 revision 유지 후 제거.

## 4. 예비 비용 분석 (바이저 픽셀당, 3240×1823 근접 위치 기준 draw 0.36 ms = rev16/17)

|항목|rev17|WF 이식|
|---|---|---|
|상태 Load|25|25(동일)|
|후보당 ALU|atan2 1 + sin 3 + 프로파일·커버리지 ~40|돔 + 합집합 ~12, 로브 2개 × ~10(sincos 대신 16-시드 상수 표)|
|장면 샘플|방울 1 + 톤 배경 1 + 수막 1 + 산란 1 = 4|방울 1 + 수막 1 + 산란 1 = 3(톤 배경 제거)|
|미분|ddx/ddy(t)|+ fwidth(U) 1|
|소스 패스|—|변화 없음(하늘 보정 불필요, §6)|

초월함수(atan2·sin)가 빠지고 장면 샘플이 1개 줄어 **draw는 rev17과 같거나 약간 낮을 것**으로 본다(예상 0.30–0.36 ms).
로브 수를 0으로 하면 더 줄어든다. 시뮬레이션 비용(frame preparation 0.39 ms)은 변하지 않는다. 메모리 추가 없음(WF의 2048² fp16 캔버스 불필요).

## 5. 표현 예비 분석과 위험

- 기대: 모든 장면에서 반전 상 + 어두운 테두리 + 아래 하이라이트로 윤곽이 서고, 기름때/알루미늄 판 문제가 사라진다. 합집합으로 닿은 방울이 자연스럽게 이어진다.
- 위험 1 — **크롬 느낌**: WF 문서의 사용자 메모(2026-09-30)에 "약간 크롬 같다, 더 흐리고 탁하게" 방향이 있었다. 손잡이: scene mip 3 → 4–5, slope mip 2.5, 굴절 0.5, 안개색 리프트 0.05–0.1.
- 위험 2 — 레퍼런스 B의 부드러운 원판: WF 선명 렌즈는 B보다 날카롭다. B 레짐에서는 aperture 디포커스(5번)로 부드럽게 하고, A·C는 WF 그대로.
- 위험 3 — 작은 방울(R < 3 px): 커널이 실루엣 임계를 못 넘을 수 있다 → 최소 그리기 반지름(기존 `minDrawMM` 개념)으로 커널만 키우고 불투명도로 보정.
- 검증: `rainfx2_refcompare.py`(레퍼런스 C/B 비율) + 사용자 시각 판정. 같은 4 프로필 T3/T4 + 기존 스크린샷과 같은 장면(나무·하늘 배경) PNG.

## 6. 굴절 소스 분석: 하늘·톤 보정이 v2에 필요한가 (사용자 질문, 2026-10-26)

결론: **필요 없다.** WF의 하늘 보정·톤 패스는 WF가 *다른 렌더*를 굴절했기 때문에 생긴 보정이고, v2는 *실제 프레임*을 굴절한다.

|항목|legacy WF|v2|
|---|---|---|
|굴절 소스|`txDynamicSnapshot` = `ac.GeometryShot`(onSceneReady에서 같은 카메라로 따로 렌더) → 톤 캔버스|`dynamic::hdr`를 그리는 순간 복사(`fallbackSource`) → `source.hlsl`(하우징 제거, 반해상도 + mip)|
|형식|GeometryShot = **R8G8B8A8 LDR**(lib.lua `ac.GeometryShot` 설명)|**RGBA16F HDR**|
|담긴 효과|WeatherFX 안개 없음, 하늘이 다름 → 먼 지형이 갈색, 하늘 경계가 "페인트" (`RAINFX_SHOT_TONE.md`)|그리는 시점(`main.smoke`, `RAIN_DYNAMIC_DROP_DRAW_AT_SMOKE_DEBUG` = true)까지 프레임에 들어간 모든 것: 조명·그림자·안개·하늘·불투명/투명 지오메트리·`main.smoke` 이전에 그려진 파티클|
|후처리|소스와 최종 화면의 후처리 상태가 달라 보정 필요|톤매핑·노출·블룸·색보정·DLSS는 **방울을 그린 뒤** 프레임 전체에 함께 적용 → 방울 안 상과 바깥 장면이 같은 처리를 받음|
|보정|하늘 → 안개색 대비 제한, 공중 원근(aerial) 안개, 톤 창, frame-first 합성(tone mode 3)|불필요. 사용자 관찰("전방 장면과 차이가 보이지 않음")과 일치|

v2에서 실제로 남는 차이와 대책:

1. **`main.smoke` 이후에 그려지는 것**(일부 파티클·연기, CSP 화면 빗방울 같은 후처리)은 방울 안에 없다. 바이저 바깥 방울이 이런 것을 굴절하지 못하는 정도라 시각적 영향은 작다.
2. **하우징:** 깊이 < 0.20 m를 지우고 push-pull로 채운다(rev5, Debug 3로 확인 완료).
3. **화면 밖 샘플:** WF 강도(0.69 × 기울기 1.3 ≈ 화면 높이 0.9)는 v2 물리값보다 2.4배 멀리 샘플한다. 화면 가장자리 방울의 반전 상은 화면 밖을 향하고
   현재는 `saturate`로 테두리 픽셀이 늘어난다. 대책: 경계에서 **거울 반사 UV** + 넘친 거리만큼 mip 증가(테두리 줄무늬 제거, 비용 ALU 몇 개).
   legacy도 같은 FOV의 GeometryShot이라 같은 한계가 있었다.
4. **HDR 밝기:** WF 값(림 손실 0.75, 글린트 0.45)은 LDR 소스에서 맞춘 것이다. HDR 소스에서는 축소된 하늘·조명이 방울 안에 더 밝게 모일 수 있다.
   보정 패스가 아니라 rev18 게임 확인에서 **방울 평균 휘도 / 배경 휘도** 비를 보고, 필요하면 소스 단계의 단순 상한(예: 최대 휘도 클램프)만 둔다.
5. 확인 방법: Debug 3(굴절 소스) 화면과 Debug 0 최종 화면을 같은 시점에서 비교 — 하늘·먼 지형 톤이 같으면 보정 불필요가 확정된다.
