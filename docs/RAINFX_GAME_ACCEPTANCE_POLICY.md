## 1. 판단 수정

**모든 중간 FP32 값의 비트 일치를 최종 게임 품질의 필수 조건으로 둔 것은 과도했다.**
비트 일치는 복사·소유권·포맷 변환 회귀를 찾는 유용한 도구지만, 재계산된 실수의
허용 오차나 실제 화면 품질과 같은 개념이 아니다. 수치가 달라도 물·운동·광학의
허용 오차 안에 있고 실행 계약이 안전하면 최적화 평가를 진행할 수 있다.

반대로 화면에서 바로 보이지 않는다고 미완료 GPU 읽기, 오래된 세대 사용, 물 복제,
시간 누락, 무한 대기나 누수를 허용하지 않는다. 이런 오류는 시간이 지나거나 조건이
바뀌면 큰 실패로 이어질 수 있다. **검증 강도는 영향과 실패 유형에 맞춘다.**

부동소수점 덧셈은 연산 순서에 따라 다른 결과를 낼 수 있고 FMA 사용 여부도 결과에
영향을 준다. [NVIDIA의 부동소수점 문서](https://docs.nvidia.com/cuda/floating-point/index.html).
이 일반 원리가 같은 CSO를 쓴 s223 차이의 원인을 입증하지는 않는다. 이번 판단은
원인 추정이 아니라 저장된 결과에서 확인한 영향 범위와 기존 수치 예산에 근거한다.

## 3. 통과의 의미를 세 단계로 분리

1. **개발/계측 진행 가능:** 실행 계약이 안전하고 관찰된 차이가 승인된 수치 예산
   안에 있다. 미해결 진단 경고를 기록하고 다음 개발을 진행할 수 있다.
2. **최적화 후보 통과:** 위 조건에 더해 목표 workload의 비용이 측정 잡음보다
   유의미하게 감소하고, 관련 상태·화면 품질 및 tail frame time이 유지된다.
3. **게임 채택:** 실제 CSP 연결, 대표 장면 A/B, 전체 비용, warm 안정성,
   pause/replay/reset 및 누적 시간 처리가 통과한다.

계측 허용을 최적화 성과나 출시 승인으로 표현하지 않는다. 새 모델은 기본 OFF
프리뷰로 실제 장면을 먼저 확인할 수 있으며, 전체 출시 조건 미측정이 프리뷰 개발을
무기한 금지하는 이유가 되지 않도록 한다. 자원·게시 안전성은 프리뷰도 지켜야 한다.

## 4. 허용하지 않는 계약 위반

- 물리 상태 NaN/Inf, 유의미한 음수 체적, 잘못된 표면/세대/연결을 사용한 유동.
- 동일 birth/merge/deposit의 이중 적용, 짝 없는 head↔film 이동, 조용한 시간 누락.
- 미완료 GPU 읽기·재사용·해제, retained immutable 입력의 실제 변조, 부분 bank 게시.
- 처리량 부족 시 증가만 하는 부채, 무한 대기·프레임 정지·제한 없는 메모리 증가.
- 표시 직경 gain만 바꿨는데 질량·부착·이동·병합·공급량이 바뀌는 결합.

작은 음수의 반올림 처리는 발생 원인·절대 크기·보존 원장을 포함해 명시적으로
검토한다. 무조건 clamp한 뒤 손실을 숨기지 않는다. 서로 다른 모델/격자를 비교할
때의 topology는 ID 비트 일치가 아니라 동일 경계·구멍·표면 영역의 보존을 뜻한다.

## 5. 새 수치/화면 기준점

아래 값은 **이 프로젝트의 초기 개발 예산**이다. 보편적인 물리 표준이나 검증된
실제 오차 상한이 아니다. 첫 CSP A/B와 비용 측정으로 조정하고 변경 이유를 남긴다.
측정하지 않은 항목은 `pending`이며 통과로 간주하지 않는다.

### 5.1 구현 최적화: 같은 모델의 계산·저장 방식을 바꿀 때

| 항목 | 초기 기준 |
|---|---|
| 중간 진단 원장 impulse/wall 재계산 | 기존 s203의 성분별 `max(1e-9, 128·FP32ε·Σabs(원장 성분))` 이내. 적용 행·단위를 먼저 지정 |
| 전체 물 재고 차이 | 기준해 대비0.05% 이내 |
| 체적의 공간 상대 L1 차이 | 0.1% 이내 |

원장 예산은 **이미 안전성이 확인된 재계산 경로의 진단 값**에만 사용한다. 복사된
바이트·헤더·상태 플래그·immutable 캐시를 허용 오차로 통과시키는 전역 `allclose`가
아니다. 지금의 저장 자료 재평가는 명시적으로1425의4/5행 xyz 성분만 대상으로 한다.
체적/기타 행이 바뀌면 이 예산으로 자동 허용하지 않는다.

정확한 최종 물 상태가 이미 일치하면 그 비교에서의 수치 퇴행은 없다고 판단할 수
있다. 동일 경로에 대한 불필요한 광학 재측정을 매 작은 수정마다 반복하지 않는다.
모델·필터·normal·굴절을 바꾼 경우에는 실제 화면 비교가 필요하다.

### 5.2 물리 근사/모델 변경: 더 싼 시뮬레이션을 선택할 때

| 항목 | 초기 기준 |
|---|---|
| birth/merge/deposit 사건 체적 원장 | 상대1e-4(0.01%) + 명시한 near-zero 절대 floor |
| 외부 공급 없는10초 closed 시험 | 누적 체적 drift≤1%; 증발·유출은 별도 원장으로 제외 |
| 동일 elapsed time의30/60/144 FPS 비교 | 전체 재고1% 및 공간 체적 L1 5%, 운동량 L1 10%를 우선 목표 |
| head/micro의 화면 직경 p10/p50/p90 | 승인 외관 대비각10% 이내를 시작점으로 A/B 평가 |
| head↔trail 연결 | 시간차1 render frame 이하, 접합 gap≤`max(1px, 표시 직경의0.25배)` |

부피 L1은 셀별 절대 차이 합을 평균 총 체적으로 나누고, 운동량 L1은 셀별 벡터
차이의 크기 합을 정상화한다. near-empty 구간은 별도의 단위 있는 절대 floor를
기록한다. 위치가 약간 다른 아주 얇은 전선의 높은 상대 오차만으로 전체 모델을
배제하지 말고 물량·화면 기여·대상 영역을 함께 표시한다. 큰 물덩어리의 잘못된
흐름·경계 통과·sheet 굴절 누락을 전체 평균으로 숨기지 않는다.

이 숫자는 서로 다른 목적이다. 사건 보존1e-4를 모든 셀 위치나 RGB에 요구하지
않으며, 모델의 공간 오차5%를 물 복제나 source 중복 허용에 사용하지 않는다.
필요하면 끝없는 dt 축소 대신 제한된 substep·해석적 stiff response·저빈도 film과
보간을 비교한다. 표시 gain은 이 모든 물리 판정을 바꾸면 안 된다.

최종 화면 px와4096×1024 atlas px를 혼동하지 않는다.6 atlas px/mm는 물리 교정값이다.
카메라 FOV/투영과 업스케일러를 고정하고 기하학적 투영과 최종 화면을 함께 본다.
물막 굴절, 부드러운 곡선, 스티커 경계의 고임·이동, FX 레이어·광원은 필수 품질이다.
Smear/local impact film은 기본 물리 표현을 평가한 뒤 필요하면 선택한다.

## 6. 비용 기준점

### 6.1 Frame time

기존 사용자 관찰의 전체 앱 증분은60% 비에서79→59 FPS, **약+4.29ms**;
100% 비에서75→45 FPS, **약+8.89ms**다. 해당 장면의 초기 퇴행 상한으로 보존한다.
다른 장면·시간·리플레이에 그대로 적용하거나 GPU 단독 비용으로 해석하지 않는다.
같은 장면의 새 기준을 측정한 뒤 갱신한다.

- 초기 개선 목표: 전체 앱 증분60% 비≤3ms,100% 비≤5ms. 아직 달성한 값이 아니다.
- 개별 최적화는 최소약0.1ms 또는 실제 잡음 범위를 넘는 이득을 확인한다. 더 작은
  이득은 합성 효과가 있거나 복잡도를 낮출 때만 선택하며 검증 단계를 증식하지 않는다.
- p95/p99 frame time이 각각0.5/1ms 이상 나빠지면 원인과 체감 영향을 검토한다.
  평균 향상으로 주기적 멈춤·급락을 상쇄하지 않는다. 잡음 이내면 불확정으로 둔다.
- 의미 있는 후보에서 같은 warmed replay의 A/B를최소3쌍×30초로 비교한다.
  출력 해상도·DLSS·날씨·축적 시간·하드웨어·카메라·진단 ON/OFF를 기록한다.
  로컬 수정마다 전체 날씨×모든 속도를 반복하지 않는다.
- 게임 프레임을 막는 synchronous readback/대기는 별도 검사한다. 독립 native의
  sleep/event 시간 차이를 CSP FPS 개선으로 제시하지 않는다.

### 6.2 Memory, 시작 지연, 작업량

64MiB solver default-texture 예산은 기존 최적화 실험의 목표로 유지하되 제품 전체의
절대 상한으로 사용하지 않는다. staging·상수/쿼리·geometry·optics·driver 오버헤드와
Lua heap을 구분해 총량/과도기 peak를 측정한다. 수 KiB 절감을 위해 비싼 복사·다수
pass를 강제하지 않는다. 메모리가 약간 늘어도 프레임 비용이 크게 줄고 전체 peak와
수명이 명확하면 새 예산 프로필에서 평가할 수 있다. 실행 중 명시한 cap 자체를
넘기거나 계수에서 빼서 통과시키지는 않는다.

통합 시 warmed10분 유지와 반복 토글을 검사한다. 안정된 조건에서 post-GC 최저값이
10분 동안 `max(5MB, warm 기준의5%)` 이상 계속 상승하면 조사 대상으로 삼는다.
한 번의 GC 전 peak나 최초 warm-up 증가만으로 누수라고 판정하지 않는다.
GPU retained/eviction은 별도 계수로 확인한다.

10초 무응답 로딩과 주기적인5 FPS/0-frame 정지는 심각한 회귀다. cold shader 준비는
진행 상태를 표시하고 프레임에 나눌 수 있어야 한다. work cap은 총 시간 부채·물량·
시각 품질을 기록해야 하며 부채가 계속 늘면 하위 품질 경로나 모델 비용을 수정한다.

## 7. 기존 사례에 실제 적용한 결과

### s223: 최적화 진행을 막는 사유에서 낮은 영향의 진단 경고로 변경

새 저장 자료 검사에서 다음을 다시 확인했다.

- 차이는 resource1425, phase20022의5개 float에만 있다.
- 바뀐 행4/5는 적용 impulse/접선 wall reaction의 xyz이며 단위는**mm³·m/s**다.
  kg·m/s나 체적 오차가 아니다. 체적 성분은 바뀌지 않았다.
- 최대 절대 차이1.2733e-11, 최대 개별 성분 상대 차이약**0.0002873%**다.
- 바뀐 성분은 기존 s203 수치 예산의 최대약0.0022%를 사용한다.
- 나머지 저장된 상태, 최종 bank, stock packets, 게시 원장, 완료·부채·소유권 기록은
  비트 단위로 같다. 직접 렌더링된 영상은 이 실험에 없다.

**판정: CPU 병목 계측은 경고를 보존하고 진행 가능.** 기존 strict 실패는 그대로
남긴다. 원인이 정상 반올림이라고 확정하지 않으며, 최적화 성능 통과나 출시 승인도
아니다. 저장된 실제 simulation 구간은약0.152초이므로 장기 오차를 입증하지 않는다.
향후 차이가 물 상태·분기·시간·게시 결과로 퍼지거나 예산을 넘으면 다시 중단한다.

### s208: 영향 미상, 해당 캐시 게시의 안전 검사 유지

새 metric과 기준값이 달랐다는 기록만 있고 실패한 값의 크기·분포가 없다. basis/area/
유효성 차이는 이동과 경계 판정에 영향을 줄 수 있다. 이를 s223처럼 작은 차이라고
취급할 수 없다. 실패 후보는 게시하지 않고 검증된 이전 캐시/정의한 fallback을 유지한다.
원인을 좁힐 자료나 fallback 증거는 해당 경로 채택 전에 필요하지만, 다른 CPU 비용
계측·UI·프리뷰 개발까지 일괄 금지하지 않는다.

### s224–s228: 충분한 진단 근거를 얻었으며 같은 방향의 반복은 종료

캡처된 합산/복사·수명·최종 축소 연산의 관계와 단독 재현은 통과했다. 원인 확정에는
못 미치지만 제품에 드러나는 오류의 증거도 새로 발견되지 않았다. 동일한 작은 실험의
정밀도를 계속 높이기보다 비용 계측과 실제 CSP 프리뷰/통합을 우선한다.

## 8. 다음 작업과 검증 범위

1. 새 실험에서는 strict 비교와 제품 의미 비교를 나란히 기록한다. 허용한 자원·단위·
   오차 예산을 사전에 지정하고 계약 위반은 즉시 중단한다. 원인 미상의 모든 값에
   전역 tolerance를 걸지 않는다.
2. s222 기반 CPU 분할 측정을 재개해 비용이 큰1–2개 구간을 선정한다. 미세한 중간
   원장 차이는 위의 제한된 조건에서 경고로 분류하며 실제 이득은 별도 측정한다.
3. 현재 모델을 실제 CSP 프리뷰로 가져가는 최소 안전 경로를 병행 설계한다. 큰
   물리/표현 오류와 실제 frame ms를 확인한 뒤 추가 정확도·메모리 최적화를 선택한다.
4. 기능 이정표에서만 전체 물리/시각 A/B와10분 warm 검사를 수행한다. 새 상태·
   경계·렌더링 오류가 보일 때 해당 검증을 강화한다.

기존 게임 물리는 s87 그대로다. 이번 변경은 판단 정책과 저장 자료 재평가이며
새 GPU 실행·게임 설치·런타임 허용 오차 수정·commit/push는 하지 않았다.


### s282 실제 적용: 상쇄된 운동량의 재고 비교 (2026-10-24)

실제 source mask32 자료에서 재고 체적은 동일했고, 운동량 성분 차이7.45e-9가
순잔량 기반4.80e-9 기준만 초과했다. 제품의 해당 재고 연속성 비교에는 이미 계산한
이전 원장 운동량 항의 절대합을 함께 사용한다. 질량 성분·128ε 계수·기타 안전 및
보존 검사는 유지한다. 실제 원인 자료·합성 cancellation 회귀·적용 범위는
[수정 기록](RAINFX_S282_INVENTORY_ROUNDOFF_REPAIR.md)에 구분한다. 이는 출고/장기
안정성 승인이 아니며, 이력이 커지는 원장 오차 예산을 무제한 절대 오차로 해석하지 않는다.


### 제품 적용: 누적 운동량과 현재 물리 상태 분리 (2026-10-25)

finite/상태/시간/자원 검사는 유지한다. 현재 상태를 진단에 맞춰 보정하지 않는다.
